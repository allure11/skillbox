# 字体排印（Typography）

> 来源：Apple HIG《字体排印》。系统字体（SF/NY）是 Apple 平台默认且推荐的字体。

## 一、确保易读性

### 默认与最小字号【强制】

| 平台 | 默认字号 | 最小字号 |
|---|---|---|
| iOS、iPadOS | **17 pt** | **11 pt** |
| macOS | **13 pt** | **10 pt** |
| Apple tvOS | **29 pt** | **23 pt** |
| visionOS | **17 pt** | **12 pt** |
| watchOS | **16 pt** | **12 pt** |

- 自定义字体同样遵循上表的默认与最小字号。
- **字重也影响易读性**：使用纤细体自定义字体时，应使用比建议字号更大的字号。
- **测试不同环境下的易读性**（各平台、各视距、明暗光照）；难读时增大字号、提高对比度或改用系统字体。
- **一般而言避免细体字重**：优先"常规体/中黑体/中粗体/粗体"，避免"极细体/纤细体/细体"，小字号时尤其禁忌。

## 二、传达层级结构

- **通过调整字重、字号、颜色强调重要信息**并表达层级；用户调整字号时，**须维持文本元素的相对层级**与视觉区分。
- **尽量减少字样数量**：混用过多字体会模糊层级、妨碍阅读，显得界面不一致。
- **响应字号更改时优先显示重要内容**：用户放大字号通常只想看清关注内容，不希望屏幕上每个字都被放大
  （例：增大标签页内容字号时，标签页标题不应随之增大）。

## 三、使用系统字体

Apple 提供两种字样系列：
- **San Francisco (SF)** — Sans Serif，含 SF Pro、SF Compact、SF Arabic、SF Armenian、SF Georgian、SF Hebrew、SF Mono；
  另有圆体变体（与柔和/圆润的界面元素协调）
- **New York (NY)** — Serif，可单独使用或与 SF 结合

- 系统以**可变字体**格式提供 SF 与 NY，支持样式间内插；支持**动态视觉字号**（自动内插字形以适配点大小），
  因此无需使用独立的视觉字号。
- SF 提供从极细体到黑体的粗细，以及窄体到阔体的宽度；SF 符号使用同等粗细，可与周围文本精确一致。
- **不要内嵌系统字体**，应通过 API 访问（SwiftUI 的 `Font.Design`；`Font.Design.default` 取系统字体、
  `Font.Design.serif` 取 New York）。

### 文本样式（Text Styles）
系统定义一组字体排印属性称为**文本样式**，综合指定字重、点大小和行距：
- **正文**样式让用户舒适阅读多行文本；**标题**样式用字号和粗细与周围内容区分。
- 使用文本样式可**自动支持动态字体**与"更大字体"无障碍设置的比例缩放。
- **考虑使用内建文本样式**；**按需通过"符号特征"修改**（如粗体特征、宽松/紧凑行距）。
  - 宽松行距：适合宽列或长段落，帮助用户从一行移到下一行时停留正确位置。
  - 紧凑行距：适合高度受限区域（如列表行内）；**若需显示三行或更多行文本，即使高度受限也应避免紧凑行距**。
- 在设计工具中，可能需要手动调整**字间距**以准确还原（运行时系统会按点大小动态调整）。

## 四、使用自定义字体

- **确保清晰易读**：以各样式与粗细的建议最小字号为下限。
- **必须实现无障碍行为**：系统字体会自动支持动态字体并响应"粗体文本"等设置；
  自定义字体必须实现相同行为，否则需提供其他调整文字大小的方式。

## 五、支持动态字体（Dynamic Type）【强制】

动态字体是 iOS、iPadOS、tvOS、visionOS、watchOS 的系统级功能，让用户调整可见文本字号。

- **确保布局适配所有字号**：验证文本与图形在所有字号下清晰易读；
  在"设置 > 无障碍 > 显示与文字大小 > 更大字体"打开"更大的无障碍字体"后验证。
- **随字号增大而增加有意义的界面图标大小**；使用 SF 符号时图标会自动缩放。
- **使文本在字号增加时最大限度保持完整**：最大无障碍字号下应能显示与最大标准字号同样多的有用文本；
  避免截断可滚动区域中的文本（除非可打开单独视图阅读其余内容）；标签可配置为按需使用任意行数。
- **考虑调整大字号下的布局**：横向受限时内联项目会挤压文本，改用堆叠式布局（文本在次要项目上方）；
  多栏文本在字号增大时减少栏数。
- **无论字号如何，保持一致的信息层级结构**（如主要元素始终保持在视图顶部）。

## 六、平台考量

| 平台 | 系统字体 |
|---|---|
| iOS、iPadOS | SF Pro（另可用 NY） |
| macOS | SF Pro（Mac Catalyst App 可用 NY）；**macOS 不支持动态字体** |
| tvOS | SF Pro（另可用 NY） |
| visionOS | SF Pro |
| watchOS | SF Compact（编译时使用 SF Compact Rounded）；另可用 NY |

**macOS 动态系统字体变体**（用于匹配标准控制中的文本外观）：

| 用途 | API |
|---|---|
| 控制内容 | `controlContentFont(ofSize:)` |
| 标签 | `labelFont(ofSize:)` |
| 菜单 | `menuFont(ofSize:)` |
| 菜单栏 | `menuBarFont(ofSize:)` |
| 信息 | `messageFont(ofSize:)` |
| 调色盘 | `paletteFont(ofSize:)` |
| 标题 | `titleBarFont(ofSize:)` |
| 工具提示 | `toolTipsFont(ofSize:)` |
| 文稿文本（用户） | `userFont(ofSize:)` |
| 等宽文稿文本 | `userFixedPitchFont(ofSize:)` |
| 粗体系统字体 | `boldSystemFont(ofSize:)` |
| 系统字体 | `systemFont(ofSize:)` |

**visionOS 专属**：
- 使用正文和标题样式的**更粗版本**；引入**特大标题 1 / 特大标题 2** 以支持较宽的编辑风格布局。
- **一般而言首选 2D 文本**：字符视觉深度越深越难阅读；需理解的内容避免视觉深度。
- 确保文本在用户缩放时美观且清晰；**最大化文本与文本容器背景的对比度**。
- 无背景文本应考虑用粗体提高易读性，**通常避免加阴影**（空间中没有可准确投影的视觉表面）。
- **尽量让文本面向用户**：与空间某点关联的文本（如 3D 对象标签）应使用"公告牌"始终面向佩戴者，保证基线垂直于视线。

| 样式 | 粗细 | 字号(pt) | 行距(pt) | 强调粗细 |
|---|---|---|---|---|

| 标题 1 | 常规体 | 25 | 31 | 粗体 |
| 标题 2 | 常规体 | 19 | 24 | 粗体 |
| 标题 3 | 常规体 | 17 | 22 | 中粗体 |

| 正文 | 常规体 | 14 | 19 | 中粗体 |
| 标注 | 常规体 | 13 | 18 | 中粗体 |
| 副标题 | 常规体 | 12 | 16 | 中粗体 |
