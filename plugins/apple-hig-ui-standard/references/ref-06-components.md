# 组件（Components）

> 来源：Apple HIG《组件》与《按钮》。组件选用遵循"用系统熟悉件优先于自造件"的总原则。

## 一、组件总则

- **优先使用系统组件**：系统组件自带交互状态、无障碍支持、外观适配与动效，
  且会自动响应无障碍设置与不同输入方式。
- **不自造已有组件**：先确认系统是否已提供等价组件（按钮、切换、弹出式按钮、分段控制、进度指示符等）。
- **组件行为与外观在 App 内保持一致**：为元素建立行为或外观后应用到整个设计。
- **控制与内容必须在视觉和位置上分离**（内容层 / 控制层）。
- **给控制留足够空间**：控制之间距离过近会导致用户误触或难以理解用途（见 `ref-05-accessibility.md` 间距规范）。

## 二、按钮（Buttons）详解

按钮用于发起**瞬时操作**。一般结合三个属性清晰传达功能：**样式**（大小/颜色/形状）、
**内容**（符号和/或文本标签）、**角色**（系统定义的语义角色）。

### 最佳实践【强制】
- **使按钮易于使用**：按钮周围留足够空间，便于从视觉上与周围组件和内容区分。
  一般规则：**至少 44×44 pt** 的点击区域（visionOS **至少 60×60 pt**），
  以确保用户用指尖、指针、眼睛或遥控器都能轻松选择。
- **始终为自定义按钮包括按压状态**：没有按压状态用户会觉得按钮无响应，怀疑是否接受输入。

### 样式
- **为视图中最有可能进行的操作使用突出视觉样式的按钮**（系统会为按钮背景应用强调色）。
  使用颜色的按钮通常最显眼，可帮助用户快速识别最可能的操作。
- **每个视图保留一到两个突出按钮**：过多突出按钮增加认知负荷，用户需花更多时间考虑选项。
- **使用样式而不是大小来区分首选选项**：相同大小的多个按钮预示它们是一组连贯选择；
  把两个不同大小的按钮放在一起会显得令人困惑且不一致。
- **避免为按钮标签和内容层背景应用相似颜色**：内容层已有鲜艳多彩内容时，按钮标签优先用默认单色外观。

### 内容
- **确保每个按钮清晰传达其用途**：可包含符号（或图标）、文本标签或两者。
- **尽量将用户熟悉的操作与熟悉的图标关联**：如 `square.and.arrow.up` 预判为共享相关操作；
  优先使用现有或自定义 SF Symbols。
- **短标签比图标更清楚时考虑使用文本**：编写简洁描述功能的少量字词，
  使用**标题式大写**，考虑让标签**以动词开头**（例："添加到购物车"）。
- macOS 和 visionOS 中，用户在按钮上悬停片刻会显示工具提示（简洁短语）。

### 角色【强制】
系统按钮可有的角色：
- **普通** — 无具体含义
- **主要** — 默认按钮，用户最有可能选取
- **取消** — 取消当前操作
- **破坏性** — 执行可能导致破坏数据的操作

规则：
- **将主要角色分配给用户最有可能选取的按钮**：主要按钮响应 Return 键，便于快速确认选择；
  在临时视图（表单、可编辑视图、提醒）中分配主要角色意味着视图可在用户按 Return 时自动关闭。
- **不要将主要角色分配给执行破坏性操作的按钮，即使该操作是最可能的选项**：
  主要按钮视觉突出，用户有时不读就点，会造成内容丢失。
- 角色会影响外观：主要按钮使用 App 强调色，破坏性按钮使用系统红色。

### 平台考量

**iOS/iPadOS**
- 需要为无法立即完成的操作提供反馈时，**配置按钮显示活动指示符**：可节省界面空间并清晰传达延迟原因；
  可配置在指示符旁显示另一标签（如"结账"→"正在结账…"）。

**macOS**（独有按钮类型）
- **推送按钮**（标准按钮）：可显示文本、符号、图标、图像或组合；可作默认按钮、可着色。
  - **仅在需要显示较高或高度可变的内容时才用灵活高度的推送按钮**；否则用标准推送按钮。
  - **推送按钮会打开另一窗口/视图/App 时，标题后附加尾部省略号**（表示用户可提供额外输入）。
  - 考虑支持**弹性加载**（拖项目到按钮上用力点按激活，不放置项目）。
- **正方形按钮**（梯度按钮）：发起与视图相关的操作（如表格增删行），包含符号而非文本。
  - **用在视图中，不用于工具栏或状态栏**（工具栏需用工具栏项）。
  - **优先采用符号**；**避免使用标签介绍正方形按钮**（其用途一般已明确）。
- **帮助按钮**：圆形问号按钮，打开 App 帮助文稿。
  - **使用系统提供的帮助按钮**；**尽可能打开与当前上下文相关的帮助主题**。
  - **每个窗口不超过一个帮助按钮**；**用在视图中而非窗口框架**；**避免显示介绍帮助按钮的文本**。
  - 位置惯例：

| 视图样式 | 帮助按钮位置 |
|---|---|
| 带关闭按钮的对话框 | 下方边角，与关闭按钮相对并垂直对齐 |
| 不带关闭按钮的对话框 | 左下角或右下角 |
| "设置"窗口或面板 | 左下角或右下角 |

- **图像按钮**：显示图像/符号/图标，行为可配置为推送按钮/切换按钮/弹出式按钮。
  - **用在视图中，不用于工具栏或状态栏**。
  - **在图像边缘和按钮边缘之间包括约 10 像素内边距**（边缘定义可点按区域，即使不可见）；
    一般不使用系统提供的边框。
  - **需要标签时放在图像按钮下方**。

**visionOS**
- 按钮通常包括视觉背景，交互时播放声音提供反馈。
- **三种标准形状**：纯图标按钮用**圆形**；纯文本按钮用**圆角矩形或胶囊形**；
  图标+文本按钮用**胶囊形**。
- 四种交互状态：空闲、悬停、已选择、不可用；**不支持自定义悬停效果**；注视片刻显示工具提示（含文本的按钮一般无需工具提示）。
- 可用尺寸：迷你 28pt / 小号 32pt / 常规 44pt / 大号 52pt / 超大号 64pt。
- **首选具有可辨背景形状和填充的按钮**：按钮显示在玻璃窗口顶部时用 `thin` 材质作背景；
  悬浮在空间中时用玻璃材质作背景。
- **避免创建白色背景填充 + 黑色文本/图标的自定义按钮**（系统保留该视觉样式表示已切换状态）。
- **一般首选圆形或胶囊形按钮**：角越圆越容易凝视；单独显示时首选胶囊形。
- **按钮中心至少相距 60 pt**；尺寸 ≥60pt 时四周加 4 pt 内边距防悬停效果重叠；
  一般避免在垂直堆栈或水平行中显示小号/迷你按钮。
- 堆栈或行中的文本标签按钮：**垂直叠放用圆角矩形，水平排列用胶囊形**。
- **使用标准控制以利用人们熟知的听觉反馈声音**（visionOS 无触感反馈）。

**watchOS**
- 所有内联按钮使用**胶囊形**；内联放在内容中时获得与背景形成明显对比的材质效果。
- **使用工具栏将按钮放在角落**（系统自动移动时间和标题容纳工具栏按钮，并应用 Liquid Glass 外观）。
- **为 App 中的主要操作优先采用横贯屏幕宽度的按钮**；
  两个按钮共享水平空间时使用相同高度，内容用图像或短文本标题。
- **使用工具栏按钮提供导航到相关区域或视图内容的关联操作**。
- **对垂直叠放的单行和两行文本按钮使用相同高度**。

## 三、按钮类组件的选型

| 需求 | 组件 |
|---|---|
| 发起瞬时操作 | **按钮**（Button） |
| 二态切换（开/关） | **切换**（Toggle） |
| 从互斥选项列表中选择一个 | **弹出式按钮**（Pop-up Button）/ 选择器 |
| 提供多个相关操作（不切换当前选择） | **下拉式按钮**（Pull-down Button） |
| 2–5 个互斥选项且需常驻可见 | **分段控制**（Segmented Control） |
| 向用户展示进度 | **进度指示符**（Progress Indicator） |

## 四、组件主题索引

官方《组件》章节按主题组织（完整主题清单见 `ref-09-catalog.md`）：
- **内容（Content）** — 图表、图像视图、文本视图、网页视图等
- **布局和组织（Layout and organization）** — 集合、列表、表格、分割视图、标签页栏、边栏、窗口、工具栏等
- **菜单和操作（Menus and actions）** — 按钮、菜单、上下文菜单、活动视图、工具栏项等
- **导航和搜索（Navigation and search）** — 导航栏、路径控制、搜索栏、搜索字段、页面控制等
- **呈现（Presentation）** — 提醒、表单、弹出窗口、操作表单、模态视图等
- **选择和输入（Selection and input）** — 选择器、切换、文本字段、滑块、步进器、分段控制等
- **状态（Status）** — 进度指示符、活动指示符、评分指示器等
- **系统体验（System experiences）** — 小组件、实时活动、通知、复杂功能、灵动岛等
