# 平台设计考量（Platforms & Games）

> 来源：Apple HIG《针对 iOS / iPadOS / macOS / Apple tvOS / visionOS / watchOS 设计》、
> 《针对 iPhone Duo 设计》（2026-09-09 新增）与《针对游戏设计》。
> **动手设计前必须先确定目标平台**——平台决定人体工程学、输入方式、系统功能与硬性数值。

## 一、平台特征速查表

| 平台 | 显示屏 | 人体工程学（视距） | 主要输入 |
|---|---|---|---|
| **iOS** | 高分辨率中等大小 | 单手或双手握持，横竖排切换；**30~60 厘米** | 多点触控手势、虚拟键盘、语音；陀螺仪/加速计；空间交互 |
| **iPhone Duo**（折叠屏） | **双屏**：外屏 compact 宽、内屏 regular 宽 | 多种姿态：闭合、书本式部分折叠、平放、立边 | 触控；**折叠时控制移至侧面** |
| **iPadOS** | 高分辨率大屏 | 手持、平面或支架；**通常 ≤90 厘米** | 触控、虚拟/实体键盘、指针设备、**Apple Pencil**、语音，**经常组合使用多种输入** |
| **macOS** | 宽大高分辨率（可接额外显示器） | 静态放桌台；**30~90 厘米** | 实体键盘、指针设备、游戏控制、Siri（**期望任意组合输入**） |
| **Apple tvOS** | 超大高分辨率 | 固定距离**通常 2.4 米/8 英尺以上**，有时边走边交互 | 遥控器、游戏控制器、语音、其他设备上运行的 App |
| **visionOS** | **无限画布**（窗口、视体、3D 对象） | 完全依赖设备相机看世界；**系统自动相对头部放置内容** | 眼睛 + 手（间接/直接手势）、数码旋钮、指针/键盘、游戏控制器 |
| **watchOS** | 小屏高分辨率 | 腕上；**≤30 厘米**；全天候显示屏 | 数码表冠、轻点/轻扫/拖移、操作按钮、快捷指令、传感器数据 |

## 二、各平台最佳实践【强制】

### iOS
1. **限制屏幕控制的数量**，同时让用户以最少的交互来发现次要细节和操作，从而**专注于主要任务和内容**。
2. **无缝适配外观变化**（设备方向、深色模式、动态字体），让用户选择最适合他们的配置。
3. **支持与用户通常手持设备的方式相适应的交互**【强制】——
   **将控制放在显示屏中间或底部区域**时用户往往可更轻易触及，
   因此**让用户轻扫以返回或在列表行中发起操作显得尤为重要**。
4. **在用户允许的情况下，整合可通过平台功能获取的信息，无需用户输入数据**
   （接受付款、生物识别认证、设备位置功能）。

**系统功能整合点**：小组件、主屏幕快速操作、搜索、Siri、活动视图。

### iPhone Duo（折叠屏）【强制】

> 来源：Apple HIG《针对 iPhone Duo 设计》（**2026-09-09 新增**）。
> iPhone Duo 是折叠屏 iPhone；**iOS 的设计模式与最佳实践依然适用**，本节的增量规则须叠加遵守。

**核心要求：先用 size classes 做自适应，不要为每种姿态单独设计布局。**

1. **基础布局宽度**【强制】：**外屏用 compact width 布局，内屏用 regular width 布局**，
   让现有布局**自然扩展而非重造**。
2. **跨姿态必须保持功能一致**【强制】：各姿态下都要提供**相同的控件与内容访问**；
   控件可以溢出、内容可以移位，但**不得丢失功能**。
3. **避免极端布局跳变**【强制】：折叠时**只移动必要元素**以保持可见易点，
   偏好**小幅调整**而非重新排列。
4. **必须构建可缩放界面**【强制】：使用 size classes、布局边距、安全区插入，
   **避免固定宽度**或依赖特定显示屏。
5. **预留区域（Reserved Regions）**（系统组件自动适应，自定义须处理）：
   - **外前置摄像头**——常驻，并会扩展为灵动岛；
   - **内前置摄像头**——仅激活时占用；
   - **折叠区域**——部分打开时分割内屏。
   API：SwiftUI 用 `ReservedRegion`，UIKit 用 `UIView.ReservedRegion`。
6. **折叠区适配**：优先让容器自动适应（如拆分视图）；**网格布局使用偶数列**；
   用 API 保证重要元素避开中心折痕。标准组件会自动调整边距避开折叠。
7. **垂直轴工具栏与标签页栏**【强制】：
   - **外屏及内屏横屏时，工具栏/标签页栏/导航控件移至侧面**以保住垂直空间；
     **内屏竖屏例外**（保留标准水平栏）。
   - 侧面区域含灵动岛、状态栏、工具栏、标签页栏；
     **控件须与硬件对齐**，且在 **RTL 语言中仍位于同侧**。
   - 跨姿态**保持控件相对位置相似**，**不要随意覆盖默认栏放置**。
   - **放置顺序**：垂直轴顶部放**主要导航**（返回/关闭），其次为 **prominent 操作**（完成）；
     频繁项优先，默认由下至上溢出，可用 `ToolbarItemVisibilityPriority` 调整顺序。
   - **空间压缩策略**：导航型界面**把工具栏压进溢出菜单保住标签页栏**；
     任务型界面**最小化标签页栏保住工具栏**；使用系统溢出菜单（`ToolbarOverflowMenu`）。
   - **邻近原则**：控件靠近其影响的内容；不需要栏的沉浸式界面可全宽，但**不得冲突灵动岛或状态栏**。
8. **游戏**【强制】：**必须在每个姿态下都可玩**；锁定向时须填满屏幕；
   调整大小时**保持文本与控件尺寸一致**，**优先改宽高比而非加黑边**；
   无法避免黑边时添加装饰图。
9. **测试**：用 Xcode 的 Device Hub 预览各姿态表现。

### iPadOS
1. **利用大屏优势突显用户关心的内容**，**尽量减少模态界面和全屏过渡动画的使用**，
   并将屏幕控制放在**用户容易触及但不妨碍使用**的地方。
2. **利用视距和输入模式来确定屏幕显示内容的大小和密度。**
3. **让用户使用多点触控手势、实体键盘或触控板或者 Apple Pencil，
   并考虑支持组合多种输入模式的独特交互方式**【强制】。
4. **无缝适配外观变化**（设备方向、多任务模式、深色模式、动态字体），
   并**轻松过渡到在 macOS 中运行**。

**系统功能整合点**：多任务处理、小组件、拖放。

### macOS
1. **利用大屏优势，通过更少的嵌套层并减少对模态的依赖来呈现更多内容**，
   同时**维持合理的信息密度**，让用户轻松看到想要的内容。
2. **让用户隐藏、显示、移动窗口和调整其大小**来适应工作方式和设备配置，
   并**支持全屏幕模式**以提供不受打扰的环境。
3. **使用菜单栏**，让用户轻松访问执行各种操作所需的**全部命令**。
4. **帮助用户充分利用高精准度的输入模式**来执行像素级选择和编辑。
5. **处理键盘快捷键**以帮助用户更快速操作和使用**纯键盘工作方式**。
6. **支持个性化**（自定义工具栏、配置窗口以显示最常用视图、选取界面中看到的颜色和字体）。

**系统功能整合点**：菜单栏、「文件」菜单、文件管理、全屏显示、程序坞菜单。

### Apple tvOS
1. **让用户在 Apple TV Remote 上使用流畅、熟悉的手势进行强大而轻松的交互。**
2. **兼容 tvOS 聚焦系统**——用户在屏幕项目之间移动时，
   系统可使用**柔和色调高亮标记并展开项目**，帮助用户始终了解要进行的操作和所在位置。
3. **提供精美的边到边图片、细致流畅的动画和动人心弦的音频**，
   使用户在房间各个位置都能沉浸于清晰易见、引人入胜的影院般丰富体验。
4. **增强多用户支持**【强制】——让**登录操作便捷并减少登录频次**，
   处理**共享登录**以及**当用户更改当前观看者时自动切换个人档案**。

**系统功能整合点**：与「视频」App 整合、同播共享、推荐项目、电视提供商账户。

### visionOS
1. **积极采用 Apple Vision Pro 的独特功能**——空间、空间音频、沉浸；
   以让用户感到轻松自然的方式集成透视和通过眼睛与手的空间输入。
2. **设计呈现 App 中最独特时刻的方式时，考虑不同的沉浸类型**【强制】——
   **为每个关键时刻找到最适合的「最低」沉浸程度，不要假设每个时刻都需要完全沉浸。**
3. **为以用户界面为中心的受限体验使用窗口**——
   帮助用户执行标准任务时首选显示为平面、包含熟悉控制的标准窗口；
   用户可将窗口重新放置在想要的任何位置，**系统的动态缩放可帮助保持窗口内容无论远近都清晰易读**。
4. **优先考虑舒适性**【强制】：
   - **在用户的视场内显示内容，并相对其头部放置**；
     **避免将内容放在用户必须转头或改变姿势才能进行交互的位置**；
   - **避免显示眼花缭乱、不和谐、过快或缺少静止参考系的动态效果**；
   - **支持非直接手势**，让用户的手放在大腿或身侧时也能与 App 交互；
   - 支持直接手势时**确保交互式内容不会距离过远，并且用户无需长时间与其交互**；
   - 用户处于全沉浸式体验中时，**避免鼓励其过多移动**。
5. **帮助用户与他人共享活动**（同播共享 + 空间自影像）。

> ⚠️ **安全提示**：驾车、操控重型机械、阳台/街道/楼梯等危险地点附近不应使用 Apple Vision Pro；
> 设备仅供 **年满 13 岁**的用户群体佩戴和使用。

**visionOS 平台特征**：
- **空间**：无限画布（窗口、视体、3D 对象）。
- **沉浸**：默认在**共享空间**启动（多 App 并排，可开关和调整窗口），
  用户可选择转换到**全空间**（只运行这一个 App，可查看与四周融合的 3D 内容、传送门或另一个世界）。
- **透视**：来自设备外部相机的实时视频，用**数码旋钮**控制透视量。
- **空间音频**：结合听觉与视觉感知技术为四周声波特征建模，自动使音频听起来自然；
  获得访问四周信息的许可后可微调空间音频。
- **无障碍**：支持旁白、切换控制、停留控制、引导式访问、头控指针等。

### watchOS
1. **支持可快速一览的单屏交互方式**【强制】——
   **简洁明了地推送重要信息，并帮助用户通过一两个简单手势执行针对性操作**。
2. **尽量减少 App 导航中的层级结构深度**，并使用**数码表冠提供垂直导航**
   以便在屏幕间滚动或切换。
3. **主动预测用户的需求**，使用设备端数据提供当前相关或即将相关的可操作内容以使体验个性化。
4. **使用复杂功能**直接在表盘上提供相关数据和图形（可为动态），让用户每次抬腕即可查看，
   还可轻点它们直接进入你的 App。
5. **使用通知推送高价值的即时信息**，让用户无需打开 App 即可执行重要操作。
6. **使用颜色等背景内容传达有用的支持信息，并使用材质说明层级结构和位置感。**
7. **将 App 设计为独立运行**，并提供额外的详细信息和功能来丰富通知和复杂功能。

**watchOS 使用特征**：
- 用户一天中会**多次查看全天候显示屏**，执行**简明的 App 交互，每次时长不到一分钟**；
- **相比 App 本身，用户通常更频繁地使用其相关体验**（复杂功能、通知、Siri 交互）；
- 用户**通常更频繁使用相关体验而非 App 本体**——设计时应优先考虑复杂功能与通知的价值。

**系统功能整合点**：复杂功能、通知、全天候显示、表盘。

## 三、针对游戏设计（Designing for Games）【强制】

### 直接进入游戏
1. **让用户在游戏安装完成后即可畅玩**【强制】——
   **不应让漫长的下载等候成为玩家的游戏初体验**；
   在初始安装中包括尽可能多的可玩内容，**将下载时间限制为不超过 30 分钟**；其他内容后台下载。
2. **提供良好的默认设置**【强制】——
   利用玩家设备信息选取最适合的默认设置（可良好呈现图形的设备分辨率、
   **自动识别已配对的配件和游戏控制器**、玩家的无障碍设置）；
   并**确保游戏支持平台最常见的交互方式**。
3. **寓「教」于乐**——把配置和用户引导流程**整合到可玩教程中**；
   文字教程应作为**可选资源**而非玩游戏的必读内容。
4. **推迟请求直至时间合适**【强制】——
   - **不要让用户在开始游戏前收到过多的请求轰炸**；
   - 使用传感器的功能**必须将请求整合到需要相应数据的场景中**
     （如初次过场动画和玩家首次可使用手部控制操作之间请求手部跟踪许可）；
   - **在请求用户评分或评价前，确保其已花时间高质量地玩过游戏。**

### 在所有显示屏上精美呈现【强制】
1. **确保文本始终清晰易读**【强制】——文本与背景形成鲜明对比，并在各平台**至少使用推荐的最小文本字号**：

   | 平台 | 默认文本字号 | **最小文本字号** |
   |---|---|---|
   | iOS、iPadOS | 17 点 | **11 点** |
   | macOS | 13 点 | **10 点** |
   | Apple tvOS | 29 点 | **23 点** |
   | visionOS | 17 点 | **12 点** |
   | watchOS | 16 点 | **12 点** |

2. **确保按钮始终易用**【强制】——按钮太小或靠得太近会使玩家不顺心：

   | 平台 | 默认按钮大小 | **最小按钮大小** |
   |---|---|---|
   | iOS、iPadOS | 44×44 点 | **28×28 点** |
   | macOS | 28×28 点 | **20×20 点** |
   | Apple tvOS | 66×66 点 | **56×56 点** |
   | visionOS | 60×60 点 | **28×28 点** |
   | watchOS | 44×44 点 | **28×28 点** |

3. **优先使用不受分辨率影响的纹理和图形**【强制】——
   无法创建时**将游戏分辨率与设备分辨率匹配**；
   visionOS 中**优先使用基于矢量的插图**（系统会随距离和角度动态缩放）。
4. **在布局中融入设备特性**【强制】——
   设备可能有可影响界面各部分的**圆角或相机防护罩**；**尽可能依赖平台提供的安全区**。
5. **确保游戏内菜单适配不同宽高比**【强制】——
   需在各种宽高比（**16:10、19.5:9、4:3**）下都良好呈现且正常运行；
   游戏内菜单尤其需要在各种设备上（支持时还需在 iPhone/iPad 的两种方向下）保持清晰易读且不遮挡其他内容；
   **考虑使用依赖相对约束的动态布局；尽可能避免固定布局**，
   **尽量仅在必要时才创建设备特定的自定义布局**。
6. **针对全屏幕体验设计**【强制】——用户通常享受无干扰的全屏幕环境。

### 实现直观交互【强制】
1. **支持各个平台的默认交互方式**【强制】：

   | 平台 | 默认交互方式 | 其他交互方式 |
   |---|---|---|
   | iOS | 触控 | 游戏控制器 |
   | iPadOS | 触控 | 游戏控制器、键盘、鼠标、触控板、Apple Pencil |
   | macOS | 键盘、鼠标、触控板 | 游戏控制器 |
   | Apple tvOS | 遥控器 | 游戏控制器、键盘、鼠标、触控板 |
   | visionOS | 触控（眼睛与手） | 游戏控制器、键盘、鼠标、触控板、空间游戏控制器 |
   | watchOS | 触控 | — |

   ⚠️ **特别注意控制的大小和菜单行为**，尤其是将游戏从**基于指针的环境推向基于触控的环境**时。
2. **支持实体游戏控制器，同时也为用户提供替代方式**【强制】——
   **除 watchOS 外每个平台都支持实体控制器，但并非每个玩家都能使用**；
   为使尽可能多的玩家畅玩，**必须提供替代交互方式**。
3. **提供基于触控且采纳 iPhone 和 iPad 上触控屏体验的游戏控制。**

### 接纳每个用户【强制】
1. **优先考虑可感知性**【强制】——无论用户使用视觉、听觉还是触觉都能感知内容；
   **避免单凭颜色传达重要细节**，或提供不包括描述性字幕、无其他阅读方式的过场动画。
2. **帮助玩家实现个性化游戏体验**——
   为玩家提供可自定义参数的功能：**字体字号、游戏控制映射、动态效果强度、声音平衡**；
   利用内建的 Apple 无障碍技术支持无障碍个性化。
3. **为玩家提供展现自我所需的工具**——
   游戏鼓励玩家创建头像或提供名字/描述时，**支持各种自我认同，提供代表尽可能多人类特征的选项**。
4. **避免在故事和角色中出现刻板印象**【强制】——
   自问游戏是否将敌人描绘成特定的种族、性别或具有特定文化传统；
   引用现实生活中的文化和语言时**确保其得当**。

### 采用 Apple 技术
- **集成 Game Center** 帮助玩家跨设备探索游戏并与朋友建立联系
  （跟踪进度和成就、排行榜、挑战、多人游戏活动）。
- **让玩家在其任何设备上都可继续游戏**（GameSave + iCloud 保存游戏状态）。
- **支持触感反馈以帮助玩家感受操作**（Core Haptics，可与自定义音频结合）。
- **使用空间音频让玩家沉浸在游戏的声景中**（多声道音频自动适应当前设备）。
- **充分利用 Apple 技术以实现独特的游戏玩法机制**
  （增强现实、机器学习、HealthKit、位置数据、相机与麦克风）。

## 四、通用平台禁忌汇总【强制】

| 平台 | 禁止 / 必须避免 |
|---|---|
| **iOS** | **避免全宽按钮**；避免在启动时显示提醒；避免为常见可撤销操作显示提醒 |
| **iPadOS** | **避免在紧凑视图中显示弹出窗口**；**避免为行后端显示控制（如显示指示符）的表格添加索引** |
| **macOS** | **禁止把关键控制放在窗口底部**；**禁止在顶部相机防护罩区域放内容**；
**避免将设置按钮添加到窗口工具栏**；**避免在工具栏或状态栏中使用开关、复选框、单选按钮**；
**不要将 App 名称用作窗口标题**；命令**不能只在工具栏呈现**（必须同时在菜单栏可用） |
| **Apple tvOS** | 内容内缩（**上下 60 pt、左右 80 pt**）；**避免显示指针**；
**约 5 种聚焦状态需逐一设计**；标签页栏高度 68 pt、上边缘距顶部 46 pt **不可更改** |
| **visionOS** | 窗口内**优先半透明至不透明颜色**；**避免创建垂直工具栏**；
**避免在工具栏中使用下拉式菜单**；**避免把内容锚定在手部或手腕上**；
系统叠层相关手势须留出区域 |
| **watchOS** | **App 不会响应按下数码表冠**（系统保留）；**避免黑色 App 图标背景**；
**避免使用透明度**（保持图像文件小）；**不要将自定义设置添加到系统「设置」App**；
**尽量避免加载指示符**（见 `ref-07`） |
