# 颜色与深色模式（Color & Dark Mode）

> 来源：Apple HIG《颜色》《深色模式》。颜色可增强沟通、体现品牌、提供视觉连续性、传达状态与反馈。

## 一、颜色最佳实践

- **避免用同一种颜色指代不同东西**：若品牌色用于表示无边框按钮可交互，就不要用相同/相近颜色去设定不可交互文本的样式。
- **确保所有颜色在浅色、深色和高对比度环境中都协调**：
  - iOS/iPadOS/macOS/tvOS 均同时提供浅色与深色外观；
  - 系统颜色会因外观不同而微调，以保证文字、符号和其他元素的区分度与对比度；
  - **"增强对比度"打开时颜色区分需更明显**；
  - 尽可能使用已为所有这些环境定义变体的系统颜色；自定义颜色须提供浅色/深色变体 + 各自的高对比度选项；
  - **即使只推出一种外观，也应提供浅色与深色**以支持 Liquid Glass 适配。
- **在不同光照条件下测试配色**：明亮环境中颜色显得更深更柔和，黑暗环境中显得明亮且饱和；
  visionOS 中颜色还会受用户现实环境墙壁/物体颜色及反射影响。
- **在不同设备上测试**：原彩显示会依据环境光自动调整白点；可在"系统设置 > 显示器"用 P3、sRGB 等描述文件测试。
- **考虑插图和半透明如何影响附近颜色**（如"地图"在地图模式用浅色方案、卫星模式切换深色方案）。
- **若 App 可让用户选颜色，优先使用系统提供的颜色控制**（内建颜色选择器提供一致体验与共享色板）。

## 二、包容性颜色【强制】

- **避免仅依靠颜色区分对象、表达交互性或传达基本信息**：必须同时提供文本标签或图形等第二种方式，
  让色盲或其他视障用户能理解。图表可允许用户自定义配色。
- **避免使用导致内容难以辨识的颜色**：对比度不足会让图标和文本融入背景；色盲用户可能无法分辨某些组合。
- **考虑颜色在其他国家及地区和文化中的理解差异**：
  红色在某些文化代表危险、在其他文化有积极含义；**中国版"股市"App 中红色表示上涨，英文版中绿色表示上涨**。

## 三、系统颜色

- **禁止硬编码系统颜色值**【强制】：文档中的颜色值仅供设计参考，实际值会随版本与环境波动；
  必须使用 `Color` / `UIColor` / `NSColor` 等 API 应用系统颜色。
- **动态系统颜色**（iOS/iPadOS/macOS/visionOS）：按**语义用途**定义而非外观值，自动适应浅色/深色。
- **禁止重新定义动态系统颜色的语义**【强制】：不把 separator 用作文本颜色，不把 secondary text label 用作背景色。

### iOS/iPadOS 前景语义色（UIKit API）

| 用于 | API |
|---|---|
| 一级内容文本标签 | `label` |
| 二级内容文本标签 | `secondaryLabel` |
| 三级内容文本标签 | `tertiaryLabel` |
| 四级内容文本标签 | `quaternaryLabel` |
| 占位符文本 | `placeholderText` |
| 分隔符（允许底层内容可见） | `separator` |
| 不透明分隔符 | `opaqueSeparator` |
| 链接文本 | `link` |

### iOS/iPadOS 动态背景色（两组，各含三级）

- **系统背景组**：`systemBackground`、`secondarySystemBackground`、`tertiarySystemBackground`
- **分组背景组**：`systemGroupedBackground`、`secondarySystemGroupedBackground`、`tertiarySystemGroupedBackground`

层级用法：
- **一级** → 整体视图
- **二级** → 整体视图内的分组内容或元素
- **三级** → 二级元素内的分组内容或元素
- **分组表格视图应使用分组背景色组；否则使用系统背景色组。**

### 系统色调色盘（SwiftUI API）
`red` / `orange` / `yellow` / `green` / `mint` / `teal` / `cyan` / `blue` / `indigo` / `purple` / `pink` / `brown`

visionOS 系统颜色使用**默认深色值**。

### iOS/iPadOS 系统灰色
`systemGray` ~ `systemGray6`（SwiftUI 中 `systemGray` 等效为 `gray`）

### macOS 动态系统颜色（常用）
`labelColor` / `secondaryLabelColor` / `tertiaryLabelColor` / `quaternaryLabelColor`、
`controlAccentColor` / `controlColor` / `controlTextColor` / `disabledControlTextColor`、
`selectedContentBackgroundColor` / `selectedTextBackgroundColor` / `selectedTextColor`、
`separatorColor` / `gridColor` / `windowBackgroundColor` / `textBackgroundColor` /
`keyboardFocusIndicatorColor` / `findHighlightColor` / `linkColor` / `placeholderTextColor` /
`alternatingContentBackgroundColors` / `shadowColor` / `unemphasizedSelected*` 系列

**macOS App 强调色**：可指定强调色自定义按钮、选择高亮、边栏图标外观；
当系统"强调色"设为**多色**时系统应用你的强调色，用户设为其它值时会覆盖你的强调色
（例外：边栏图标使用固定颜色，不随强调色设置改变）。

## 四、Liquid Glass 颜色

- Liquid Glass **默认无固有颜色**，直接采用后方内容的颜色；可将颜色应用于部分元素，赋予染色/彩绘玻璃外观。
- **谨慎将颜色应用到 Liquid Glass 材质以及材质上的符号或文本**【推荐】：
  - 颜色只留给真正值得强调的元素（状态指示符、主要操作）；
  - 强调主要操作时**把颜色应用到背景而非符号或文本**（系统即把强调色应用到突出按钮背景）；
  - **避免为多个控制的背景添加颜色**。
- **如果 App 具有彩色背景，避免在控制标签中使用相似颜色**；
  彩色背景或丰富视觉内容时，工具栏和标签页栏优先**单色外观**或选取足够区分度的强调色；
  主要单色内容的 App 用品牌色作强调色是有效的个性化方式。
- **注意颜色在内容层中的放置**：避免在内容层与控制中重叠使用相似颜色；
  彩色内容可能滚动到控制下方，但默认/静止状态必须保持清晰易读。

## 五、深色模式（Dark Mode）

深色模式是系统范围的外观设置，使用深色调色盘为低光环境提供舒适浏览体验。

### 最佳实践
- **避免提供 App 特定的外观设置**【强制】：App 专属外观选项会增加用户工作量，
  且用户会认为 App 有问题（因为没跟随系统设置）。
- **确保 App 在两种外观模式下都很好地呈现**：用户可能选取"自动"，在 App 运行期间切换外观。
- **测试两种外观下的舒适易读性**：在"增强对比度"和"降低透明度"（分别或同时）打开时的深色模式下，
  深色背景上的深色文本不易辨认——这是不合格的。
- **极少数情况可考虑只用深色外观**（如沉浸式观看媒体的 App，深色有助专注内容）。

### 深色模式颜色
- 调色盘包含较暗背景 + 较亮前景；**这些颜色不一定是浅色颜色的反转**（很多是反转的，但有些不是）。
- **包含适合当前外观的颜色**：语义色（macOS 的 `labelColor`/`controlColor`，iOS 的 `separator` 等）自动适配；
  自定义颜色需在素材目录的"颜色集"中指定亮/暗变体；**避免硬编码不可自适应的颜色值**。
- **力求所有外观都有足够对比度**：至少 **4.5:1**；**自定义前景/背景色尽量做到 7:1，小文本尤其如此**。
- **柔化白色背景的颜色**：内容图像含白色背景时应略微调暗，防止在深色环境中发光。

### 图标和图像
- **尽可能使用 SF 符号**：配动态颜色或虚化效果时，在两种外观下都不会有问题。
- **必要时为浅色/深色分别设计界面图标**：如满月图标在浅色背景需微妙深色轮廓，深色背景则不需要；
  油滴图标在深色背景可能需要细边框才能看到边缘。
- **确保全彩图像和图标在两种外观中都有效**；只在一种模式下有效时，修改素材或分别创建两套，用素材目录合并为单一命名图像。

### 文本
- **为标签使用系统提供的标签颜色**（一至四级标签色自动适配）。
- **使用系统视图绘制文本栏和文本视图**：系统视图会根据是否存在虚化效果自动调整，比自行绘制更可靠。

### 平台考量
- **iOS/iPadOS**：深色界面叠加时系统用**基本色**（更暗，背景界面看似后退）和**提升色**（更亮，前景界面看似前进）
  两组背景色增强深度感知；弹出窗口或模态表单在前景时背景色会**自动从基本色变为提升色**。
  **优先使用系统背景颜色**——自定义背景色会破坏系统提供的深度与多任务/多窗口视觉分离。
- **macOS**：用户选"石墨色"强调色时，窗口背景会从桌面图片提取颜色（**桌面着色**）。
  适当时候可在自定义组件背景加入透明度（仅对背景/外框可见的中性状态组件加透明度；
  **使用颜色的状态下不加透明度**，否则颜色会随桌面变化而波动）。
- **visionOS、watchOS 不支持深色模式。**
