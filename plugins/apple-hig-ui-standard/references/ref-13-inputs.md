# 输入方式（Inputs）

> 来源：Apple HIG《输入》分组全部 13 个主题：手势、键盘、指针设备、聚焦和选择、遥控器、
> 数码旋钮/表冠、眼睛、游戏控制、操作按钮、Apple Pencil 和随手写、相机控制、陀螺仪和加速计、近场交互。
> 输入方式决定**点击目标尺寸、焦点模型、手势约定**——做交互设计前必须先确定目标输入方式。

## 一、手势（Gestures）

### 标准手势（全平台通用基础）
| 手势 | 支持系统 | 常用操作 |
|---|---|---|
| 轻点 | 全部 | 激活控制；选择项目 |
| 轻扫 | 全部 | 显示操作和控制；关闭视图；滚动 |
| 拖移 | 全部 | 移动界面元素 |
| 按住（或捏住） | iOS/iPadOS/tvOS/visionOS/watchOS | 显示更多控制或功能 |
| 轻点两下 | 全部 | 放大；已放大则缩小；Apple Watch Series 9 / Ultra 2 上执行**主要操作** |
| 缩放 | 除 watchOS | 缩放视图；放大内容 |
| 旋转 | 除 watchOS | 旋转所选项目 |

**iOS、iPadOS 附加手势**：
- **三指轻扫**：向左发起撤销，向右发起重做
- **三指开合**：捏合拷贝所选文本，张开粘贴
- **四指轻扫**（仅 iPadOS）：在 App 之间切换
- **摇动**：发起撤销 / 重做

### 最佳实践【强制】
1. **为用户提供不止一种与 App 交互的方式。**
   用户可能更喜欢或用**语音、键盘、切换控制**等输入方式；**不要假设用户可以使用特定手势执行给定任务**。
2. **响应手势的方式必须与用户预期一致。**【强制】
   避免用轻点、轻扫等熟悉手势执行**专属于你 App 的操作**；
   同样**避免创建独特手势来执行标准操作**（激活按钮、滚动长视图）。
3. **尽可能快地处理手势**，提供即时反馈，必要时告知完成操作所需的移动范围与类型。
4. **向用户表明手势不可用的情况。**【强制】
   不说明原因时，用户会以为 App 已停止响应或自己操作有误。
   例：拖移锁定对象无任何提示；不可用按钮与可用状态无明显区别。

### 自定义手势（仅在必要时）
自定义手势必须：**易于发现、操作直观、区别于其他手势、不是执行重要操作的唯一方式**。
- **让自定义手势简单易学**：若难以用简单语言和图形描述，说明用户会觉得难以学习。
- **用快捷手势补充而非替换标准手势**（如同时提供「返回」按钮和边缘轻扫）。
- **避免与访问系统 UI 的手势冲突。**【强制】
  例：watchOS 轻扫边缘、visionOS 翻手访问系统叠层。
- **允许同时识别多个手势**（游戏中摇杆 + 发射按钮）。
- **visionOS 自定义手势**：优先考虑舒适性（长时间举手臂会疲劳）；
  谨慎对待多指/双手复杂手势；**避免需要用某一只手才能执行的手势**。
  - **将用户手部周围的区域留给系统叠层及其相关手势**——尽量不把内容锚定在手部或手腕上。
  - **谨慎设计需要转动手部、手腕和前臂的自定义手势**（该动作为显示系统叠层保留）。

### visionOS 手势类型
| 类型 | 机制 | 适用 |
|---|---|---|
| **间接手势** | 先**注视**目标聚焦，再用手从远处操控（如互点拇指与其他手指选择） | 任意距离舒适执行；**常见 UI 和按钮优先用间接手势** |
| **直接手势** | 实际接触交互式对象（如轻点虚拟按键） | 可触及范围内效果最好；**不宜频繁使用**（长时间举手臂疲劳） |

**尽可能同时提供间接和直接交互方式。**
标准直接手势：轻触（选择/激活）、按住（打开关联菜单）、轻触并拖移（移动对象）、
轻触两下（预览对象/文件；编辑情境中选择字词）、轻扫（显示控制、关闭视图、滚动）、
双手捏合并拖移（缩放）、双手捏合并沿圆弧拖移（旋转）。

**避免需要特定身体移动或姿势来输入。**【强制】
并非所有人都能执行特定身体动作，体验涉及动作时应支持备选输入方式。

### watchOS 互点两下（Double Tap，watchOS 11+）
- 可用于滚动列表和滚动视图、在垂直标签页视图间导览；可把开关/按钮指定为 App、小组件或
  智能叠放实时活动的**主要操作**；也用于通知中的**第一个非破坏性操作**。
- **避免在包含列表的视图、滚动视图或垂直标签页中设置主要操作**——与默认导览行为冲突。
- **选取用户最常使用的按钮作为主要操作。**

## 二、键盘（Keyboards）

> watchOS 不支持。

### 最佳实践【强制】
1. **尽可能支持全键盘控制。**【强制】
   iOS、iPadOS、macOS、visionOS 提供全键盘控制。
   ⚠️ **避免为按钮、分段控制、开关等控件单独实现键盘导航**——
   应让用户用全键盘控制来激活控件、导航到所有屏幕组件，甚至执行拖放等手势交互。
2. **遵循标准键盘快捷键。**【强制】
   ⚠️ **通常不要将标准快捷键改用于自定义操作**——用户会感到困惑。
   仅当标准快捷键的操作在你的体验中不可行时才重新定义
   （如不支持文本编辑的 App 可将 Command–I 用于「显示简介」）。
   需频繁执行的独特操作应**新建自定义快捷键**，而非改变标准快捷键用途。
3. **自定义快捷键规范**【强制】：
   - **仅为最常用的 App 特定命令定义**（过多新快捷键会让 App 显得难以上手）。
   - **修饰键用法**：Command 作为**主**修饰键；Shift 作为**辅助**修饰键补充相关快捷键；
     Option 谨慎用于不太常见的命令或强大功能；**避免将 Control 用作修饰键**
     （系统在大量全系统范围功能中使用它）。
   - **列出顺序固定为：Control、Option、Shift、Command。**
   - **避免在使用双字符键高位字符的快捷键中添加 Shift**——直接写高位字符更清楚
     （「隐藏状态栏」是 Command-斜线，「帮助」是 Command-问号，而非 Shift-Command-斜线）。
   - **避免基于无关命令的现有快捷键加修饰键来新建快捷键**（如把 Shift-Command-Z 用作与撤销/重做无关的命令）。
   - 系统会**自动本地化与镜像**快捷键。

### 标准快捷键要点（macOS 生态）
- 空格：Command-空格（聚焦）、Option-Command-空格（聚焦结果窗口）、Control-Command-空格（特殊字符）
- Tab：Shift-Tab 反向导航；Command-Tab / Shift-Command-Tab 切换 App；Control-Tab 移动焦点到下一控制组
- Esc：取消当前操作；Option-Command-Esc 强制退出
- F 系列：Control-F1 开关全键盘控制；Control-F2 菜单栏；Control-F3 程序坞；Control-F4 窗口；
  Control-F5 工具栏；Command-F5 旁白；Control-F6 面板；Control-F7 覆盖键盘控制模式；F11 显示桌面
- Command-A 全选 / Shift-Command-A 取消全选；Command-C/V/X 拷贝/粘贴/剪切；
  Command-Z 撤销 / Shift-Command-Z 重做；Command-S 保存；Shift-Command-S 保存为；
  Command-W 关闭窗口；Option-Command-W 关闭所有窗口；Command-Q 退出；
  Command-逗号 打开 App 设置；Command-问号 打开帮助菜单；Command-句点 取消操作；
  Command-N 新建；Command-O 打开；Command-P 打印；Command-F 查找；Command-G / Shift-Command-G 查找下一个/上一个
- **visionOS**：App 的快捷键出现在**快捷键界面**（按住 Command 键时显示），
  按系统定义菜单类别（文件、编辑、显示）以**扁平列表**显示所有可用且有快捷键的命令。
  ⚠️ **必须编写描述性快捷键标题**——扁平列表中没有子菜单标题提供语境。

## 三、指针设备（Pointing Devices）

> iOS 无额外考量；tvOS 与 watchOS 不支持。

### 最佳实践【强制】
1. **响应鼠标和触控板手势时保持一致性**（如「在页面之间轻扫」在全系统行为一致）。
2. **避免重新定义系统范围的触控板手势。**【强制】
3. **无论用户用手势、眼睛、指针设备还是键盘，都提供一致的体验**——
   用户期望在多种输入类型间流畅切换，不想为每种模式学习不同的交互。
4. **让用户使用指针来显示和隐藏可自动最小化或淡出的控制。**
5. **用户按住修饰键并与对象交互时提供一致体验**（如 Option 拖移复制，无论触控还是指针结果应一致）。

### iPadOS 指针系统
- **指针形状**默认圆形，移到特定元素上时自动切换（文本输入区 → 工字型）。
- **三种内容效果**：

| 效果 | 表现 | 系统默认应用 |
|---|---|---|
| **高亮标记** | 指针转为半透明圆角矩形作为控制背景，带轻微视差 | 栏按钮、标签页栏、分段控制、编辑菜单；**背景透明的小元素** |
| **提升** | 轻微视差 + 升高外观（放大、下方阴影、顶部柔和镜面高光） | App 图标、控制中心按钮；**背景不透明的小元素** |
| **悬停** | 通用效果，为元素应用自定义缩放、着色、阴影；**不转换默认指针形状** | **大元素** |

- **指针配件**：视觉指示符（如可调整大小元素的箭头），可与任何指针结合。
  **使用清晰简单的图像**；**考虑用配件过渡表示元素状态或行为改变**
  （如从 `plus` 符号过渡到 `circle.slash`）。
- **指针磁吸**：指针靠近或快速移向元素时被吸向该元素中心。
  系统默认为提升效果和高亮标记效果的元素应用，**悬停效果的元素除外**
  （会导致不协调、失去控制感）；文本输入区也会应用（避免选择文本时垂直移动跳到另一行）。
- **点击区域**【强制】：
  **包含外框的元素四周添加约 12 点内边距效果很好；无外框元素在可见边缘四周添加约 24 点效果很好。**
  ⚠️ 点击区域过小 → 用户觉得必须格外精确；过大 → 用户觉得把指针拉离元素很费劲。
- **为自定义栏按钮创建连续点击区域**（相邻按钮间有间隔会导致指针短暂复原到默认形状，分散注意力）。
- **指定接收提升效果的非标准元素的圆角半径**（圆形等非矩形形状必须提供，否则指针无法无缝转换）。
- **自定义指针规范**【强制】：
  - 优先用系统提供的效果（**自定义元素行为类似标准元素时用户期望熟悉的指针交互**）；
  - 全 App 使用一致的指针效果；**避免创建无实际价值的纯装饰性指针效果**；
  - 自定义指针形状应**保持简单**，理想情况下形状代表当前环境可执行的操作；
  - **避免通过指针显示指导性文本**；
  - 定义自定义悬停效果时考虑阴影、缩放与元素间距的相互作用
    ——**缩放不适用于表格行**（行无法在不与相邻行重叠的情况下展开）；
    周围空间很小的元素应考虑**仅着色、不缩放不阴影**的悬停效果；
    **不含缩放的阴影效果不佳**（未缩放元素不会显得更接近观看者）。

### macOS
- 标准交互：首选点按（选择/激活）、辅助点按（关联菜单）、滚动、智能缩放、在页面之间轻扫、
  全屏 App 之间轻扫、调度中心、查询和数据检测器、轻点来点按、用力点按、放大缩小（双指开合）、
  旋转（双指圆周运动）、通知中心（边缘轻扫）、App Exposé、启动台、显示桌面。
- **标准指针样式表**（部分）：箭头 `arrow`（选择内容与界面元素）、
  **紧握的手 `closedHand`**（拖移调整内容显示位置）、**关联菜单 `contextualMenu`**（按下 Control 时显示）、
  十字线 `crosshair`（精确矩形选择）、**使项目消失 `disappearingItem`**（拖移项目放下后消失，原始项不受影响）、
  **拖移副本 `dragCopy`**（按住 Option 拖移）、**拖移链接 `dragLink`**（按住 Option+Command 拖移，创建替身）、
  水平工字型 `iBeam`、**张开的手 `openHand`**（可在视图中拖移调整内容位置）、
  **操作不被允许 `operationNotAllowed`**（不能在当前位置放下）、
  指向某处的手 `pointingHand`（URL 链接）、向下/左/右/上调整大小及其组合、
  垂直工字型 `iBeamCursorForVerticalLayout`。

### visionOS
- 用户可外接指针或键盘，同时继续使用眼睛和手。
  用户注视某元素后移动指针，系统会聚焦到指针下方的元素（**App 无需做任何事**）。
- **连接指针设备后，用户注视的区域决定指针的上下文**，视线从一个窗口移到另一个时上下文无缝转换。
- 使用支持手势的指针设备时，指针在使用手势时**隐藏**，直至用户移动后重新出现在注视位置。

## 四、聚焦和选择（Focus and Selection）

> iOS 或 watchOS 不支持。

**聚焦**支持基于组件的简化导航；许多情况下聚焦同时也选择项目。
不同平台表示焦点的方式不同：iPadOS/macOS 用**圆环或高亮标记**；tvOS 用**视差效果**赋予深度与活力。

### 最佳实践【强制】
1. **借助系统提供的聚焦效果。**【强制】
   系统定义的聚焦效果经过精确调整；仅在确实必要时才考虑创建自定义聚焦效果。
2. **避免在用户未交互时更改焦点。**【强制】
   用户依赖聚焦系统了解自己在 App 中的位置。
   - **例外**：用户使用**不连续定向移动**的输入设备（键盘、遥控器、游戏控制器）移动焦点时，
     之前获得焦点的项目消失 → 将焦点移到剩余项目中的一个，确保焦点指示符位于用户可轻易找到的位置。
   - 用户未使用此类输入设备时，**直接隐藏焦点指示符**通常是最佳做法。
3. **帮助用户聚焦项目时与系统保持一致**：
   - **iPadOS/macOS 全键盘控制模式**下，只需支持**列表项、文本栏、搜索栏等内容元素**的聚焦，
     **不需要**支持按钮、滑块、开关等控件；
   - **tvOS** 用户需用定向手势访问**每个屏幕元素**，因此**必须确保用户可聚焦 App 中的每个元素**。
4. **使用与系统一致的视觉外观表示焦点**（如获焦列表项用白色文本 + 强调色背景高亮；
   未获焦用标准文本色 + 灰色背景高亮）。
5. **一般应为文本或搜索栏使用焦点环，在列表或集合中使用高亮标记。**

### iPadOS — 焦点组
- **Tab 键**在焦点组间移动焦点（边栏、网格等 App 区域）；**箭头键**在**同一焦点组内**做定向导航。
- **光环（焦点环）焦点效果**：在组件周围显示可自定义外框，可应用到自定义视图及集合/列表单元格中不透明的内容。
  **必要时自定义光环**（系统默认用项目形状推断光环形状；可用圆角或贝塞尔路径匹配轮廓，
  也可调整位置以避免被遮挡或截断）。
- **高亮标记外观**：组件文本使用 App 强调色，指示焦点但不是焦点效果。
- **确保焦点以可行方式在自定义视图中移动**：Tab 移动遵循阅读顺序（开头→末尾、顶部→底部）。
  可将垂直堆栈容器标识为**单个焦点组**以调整访问顺序。
- **调整项目优先级以反映其在焦点组中的重要性**——组获得焦点时其**主要项**也自动获得焦点。

### tvOS【强制】
1. **在全屏幕体验中，让用户使用手势与内容交互，而非移动焦点。**
2. **避免显示指针。**【强制】
   用户希望通过更改焦点在固定数量项目间导航，不希望在大屏上拖移很小的指针
   （自由移动在寻找隐藏物品、开飞机等游戏中有意义）。若确需指针，须非常显眼且与体验高度协调。
3. **设计界面时顾及组件的各种聚焦状态。**【强制】可聚焦项目**最多有五种状态**：
   | 状态 | 描述 |
   |---|---|
   | 未获得焦点 | 不如已获得焦点的项目显眼 |
   | 获得焦点 | **升高至前景 + 添加高亮和动画**，比其他屏幕内容更突出 |
   | 被选取 | 提供**即时视觉反馈**（如按钮短暂反转颜色并显示动画） |
   | 已选中/已激活 | 如心形按钮已选中为实心、未选中为空心 |
   | 不可用 | 显示为不活跃状态，无法聚焦或选取 |
   ⚠️ **将焦点移到项目通常会放大其比例**，需提供**获得焦点的更大尺寸资源**，
   并确保更大的项目不会挤到周围的界面。

### visionOS
- 支持与 iPadOS/tvOS 相同的聚焦系统（用键盘或游戏控制器等连接的输入设备）。
- ⚠️ **用户注视虚拟对象时，系统使用「悬停效果」而非「聚焦效果」提供视觉反馈**
  （悬停效果与聚焦系统无关）。

## 五、遥控器（Remotes，Apple tvOS 专有）

> iOS、iPadOS、macOS、visionOS、watchOS 不支持。

Apple TV Remote 结合点按板与触控表面，支持轻扫和按下等熟悉手势。

### 最佳实践【强制】
1. **优先使用标准手势以执行标准操作。**【强制】
   重新定义或改变标准遥控器行为会导致困惑并增加复杂度（除用户正在积极玩游戏）。
2. **与 tvOS 焦点体验保持一致**——手势与焦点结合方式须与用户熟悉的方式一致（如焦点始终朝手势移动方向移动）。
3. **提供清晰反馈展示手势结果**（如拇指轻放时展示在哪里向下轻扫可显示信息区域）。
4. **仅在 App 中可行时才定义新手势。**
5. **区分「按下」和「轻点」，避免响应无意轻点。**【强制】
   「按下」是有意操作（选取按钮、确认选择、游戏中发起操作）；
   用户将拇指放在遥控器上、拿起、移动或交给他人时都可能产生**无意轻点**，
   **在视频播放过程中避免响应轻点**通常效果更佳。
6. **考虑利用轻点的位置辅助导航**（可区分上/下/左/右轻点），仅当位置轻点在当前环境中有意义且直观可发现时才响应。
7. **几乎所有情况下，用户按下「返回」按钮时打开当前屏幕的父屏幕。**【强制】
   - 顶层 App 的父屏幕是 Apple TV 主屏幕；App 内父屏幕由 App 层级定义，**不一定是上一个屏幕**。
   - **例外**：用户正在积极玩游戏时，容易意外重复按下「返回」→ 应通过**打开游戏内暂停菜单**响应；
     暂停菜单打开时，再次按下则**关闭菜单并继续游戏**。
   - 提示：**按住「返回」按钮可从任意位置前往主屏幕。**
8. **媒体播放期间正确响应播放/暂停按钮**（播放、暂停或继续播放）。

### 按钮映射表【强制】
| 按钮/区域 | App 中的预期行为 | 游戏中的预期行为 |
|---|---|---|
| 触控表面（轻扫） | 导航；更改焦点 | 执行**方向键**行为 |
| 触控表面（按下） | 激活控制或项目；更深入地导航 | 执行**主按钮**行为 |
| 背面 | 返回上个屏幕；退出到 Apple TV 主屏幕 | 暂停/继续游戏；返回上个屏幕、退出到游戏主菜单或 Apple TV 主屏幕 |
| 播放/暂停 | 激活媒体播放；暂停/继续播放 | 执行**辅助按钮**行为；跳过简介视频 |

### 兼容遥控器（含 EPG 按钮）
- 用户按下「指南」或「浏览」按钮时期望**打开 EPG**；浏览 EPG 时用「上一页 / 下一页」导航；
  **用户浏览 EPG 时避免以其他方式响应这些按钮**；也可轻点触控表面的上/下区域浏览 EPG。
- **内容播放时，以更换频道的方式响应「上一页 / 下一页」按钮。**

## 六、数码旋钮 / 表冠（Digital Crown）

> iOS、iPadOS、macOS、tvOS 不支持。

**Apple Vision Pro 数码旋钮用途**：调整音量；调整传送门/环境/全空间 App 的沉浸程度；
重新居中内容于用户面前；打开无障碍设置；退出 App 并返回主屏幕视图。

**Apple Watch 数码表冠**（watchOS 10+ 起为主要导航输入）：
- 表盘上旋转查看**智能叠放**中的小组件；主屏幕上垂直浏览 App 集；
  App 内垂直切换编页的标签页、滚动列表视图和高度可变页面。
- ⚠️ **App 不会响应按下数码表冠的行为**——watchOS 为系统功能（显示主屏幕）保留了该交互。
- 触感反馈：旋转到一定幅度时系统默认提供**线性定位**或轻点反馈；表格视图在新项目滚动到屏幕时提供定位。

规则【强制】：
1. **将 App 的导航锚定到数码表冠上。**【强制】
   从 watchOS 10 起旋转表冠是 App 内和 App 间导航的主要方式；
   列表、标签页、滚动视图应**垂直布局**；
   **必须同时提供相应的触控屏交互作为备选方案。**【强制】
2. **考虑在不需要导航的情况下使用数码表冠检查数据**（如「世界时钟」旋转表冠前进到所选位置的时间）。
3. **提供响应数码表冠交互的视觉反馈。**【强制】
   不提供视觉反馈时，用户很可能会认为旋转表冠在 App 中不起作用（如选择器应更改当前显示的值）。
4. **更新界面以匹配用户旋转数码表冠的速度**——避免以用户难以选择值的速度更新内容。
5. **如果在 App 中可行，请使用默认触感反馈**；不适用时可关闭该类定位，
   也可让表格使用**线性定位**而非基于行的定位（行高明显不同的表格）。

## 七、眼睛（Eyes，visionOS 专有）

> iOS、iPadOS、macOS、tvOS、watchOS 均不支持。

用户注视交互式元素时，visionOS **高亮标记**它（**悬停效果**），提示用户可用轻点等非直接手势交互。
某些情况下系统会在用户注视后自动显示展开视图（如注视标签页栏时整个栏展开显示文本标签）。

> 🔒 **隐私红线**：visionOS **不会在用户轻点前提供其所看位置的直接信息**。
> 使用系统提供的组件时，系统会在用户轻点该组件时自动告知。**不得试图绕过。**

### 最佳实践【强制】
1. **始终向用户提供多种与 App 交互的方式。**
2. **以视觉舒适性为设计目标。**【强制】
   确保用户需要使用的对象位于其**视场**内；避免要求用户在较大区域内或多个深度级别间进行多次快速眼睛调整。
   - head-mounted 时系统会自动把首个窗口/视体放在用户面前方便的位置；
     全空间 App 可请求头部姿态信息以正确放置 3D 内容。
3. **将内容放在看起来舒适的距离处。**【强制】
   **帮助用户在长时间阅读或体验期间保持舒适，请尽量将其放在至少一米远的位置。**
   除非用户仅在很短时间内查看或交互，否则不应放在距用户很近的位置。
4. **优先使用标准用户界面组件**——系统组件的注视响应一致；自定义组件用不同视觉提示会导致用户难以学习和记忆。

### 让项目显而易见
1. **尽量减少视觉干扰。**【强制】
   视觉噪声过多时用户难以找到对象；**视觉移动的干扰性更强**
   （用户在周边视觉范围内感知到移动时会无意识地注视它）。
   例：在用户正注视的按钮附近显示内容，会导致用户不由自主地注视新内容。
2. **在项目周围留出足够空间让用户可轻松注视。**【强制】
   即使注视一处，人眼也会自然进行小幅快速方向调整。
   **每个项目边界周围使用至少 16 点的外边距，或使项目中心始终相距至少 60 点。**
3. **避免使用填满视场的重复图案或纹理**（人眼可能锁定在图案不同元素上，使其看起来深度不同）；
   考虑在较小区域内使用图案。

### 鼓励交互
1. **考虑使用精细的视觉提示鼓励用户注视最可能想用的项目**：放在视场中心附近，
   或使用柔和的动态效果、增强对比度、颜色或缩放变化。**首选明显但不鲜艳或刺眼的提示。**
2. **一般应为交互式项目使用圆角形状。**【强制】
   视线常被形状的角吸引，难以保持注视中心；**角越圆，用户越容易用眼睛定位该项目**。
3. **包含多个元素的交互式组件须提供一个整体的容器形状**，使 visionOS 可高亮标记该形状
   （如图像及其下方标签组合时应自定义包含两者的区域）。

### 自定义悬停效果
- 机制：为元素创建**两种状态/外观**（显示与不显示自定义悬停效果）。
  系统在**软件进程之外**的进程中应用预定义效果
  → ⚠️ **你无法掌握系统何时应用效果，也不知道元素当时的状态**；
  自定义悬停效果**无法运行需要得知用户何时注视元素的代码**。
- **优先用于强调或增强体验中的特别时刻**（标准效果已足够时使用会淡化设计影响力、分散注意力甚至导致视觉不适）。
- **选择适合的延迟**：
  - **无延迟（默认）**：效果微妙或鼓励交互时（如滑块上显示旋钮）；
  - **短延迟**：让用户可与注视元素迅速交互而无需等待（如标签页展开）；
  - **长延迟**：显示附加信息时（如按钮下方工具提示），大多数用户不需要每次都看。
- **尽量使元素的一个或多个主要视图在两种状态下保持不变**【强制】——
  提供视觉稳定性帮助用户跟随过渡；所有视图都移动变化会让用户失去方向感。
- **全面测试自定义悬停效果**，尽量佩戴 Apple Vision Pro 培养直觉。

## 八、游戏控制（Game Controls）

> watchOS 不支持。

**同时支持平台默认交互方式的原因**：并非每位玩家都能使用实体控制器；玩家青睐最熟悉平台交互方式。

### 触控控制（iOS/iPadOS）
1. **确定在游戏内容上显示虚拟控制是否有意义**——
   大量操作或要求控制移动时有用；玩家可直接与游戏内对象交互时沉浸感更好。
   **选择将操作与游戏内手势关联来尽量减少与内容重叠的虚拟控制数量**
   （如让玩家轻点选择对象，而非添加虚拟选择按钮）。
2. **将虚拟按钮放在易于触及的位置。**【强制】
   考虑设备边界、**安全区**和易于控制的位置；
   **确保按钮摆放不与 iPhone 主屏幕指示符或灵动岛等系统功能重叠**；
   常用按钮放在**拇指附近**，**避开预期会出现移动和镜头输入的圆形区域**；
   菜单等次要控制放在**屏幕顶部**。
3. **确保控制足够大。**【强制】
   **常用控制不小于 44×44 点，菜单等次要控制不小于 28×28 点。**
4. **始终包括可见的触觉按压状态。**【强制】
   没有可视物理按压状态的虚拟控制会让人感觉无响应；
   添加玩家手指盖住控制时也能看见的按压状态效果（如光晕），并结合声音与触感。
5. **使用传达所执行操作的符号**（用武器图形代表攻击）；
   **避免将抽象形状或基于控制器的命名（A、X、R1）用作插图。**
6. **显示和隐藏虚拟控制以反映游戏玩法**（操作不可用或不相关时隐藏，减少杂乱）。
7. **将功能并入单个控制**（用轻点两下、按住提供同一动作的变体）。
8. **将移动和镜头控制映射至可预测的行为**：
   通常**左侧控制移动、右侧控制镜头**；用尽可能大的输入区域；
   移动控制应在**玩家放拇指的位置**而非静止摇杆位置显示虚拟摇杆；
   镜头控制**优先用直接触控**而非虚拟摇杆来平移。

### 实体控制器
- **支持平台的默认交互方式**【强制】——须提供使用平台默认交互方式（触控/键盘鼠标/遥控器/眼与手）的回退功能。
- **告知用户需要游戏控制器**（App Store 显示「需要游戏控制器」标记；须检查是否存在并友好提示连接）。
- **自动检测控制器是否已配对**，不要让玩家手动设置。
- **自定义屏幕内容以匹配连接的游戏控制器**——在界面中指代控制或显示相关内容时，
  **必须使用所连接控制器的标记方案**（框架分配的标准名称与实物颜色/符号可能不同）。
- **控制器按钮映射**【强制】：
  | 按钮 | 非游戏状态下 UI 的预期行为 |
  |---|---|
  | A | 激活控制 |
  | B | 取消操作或返回上个屏幕 |
  | 左肩键 | 向左导览至另一屏幕或部分 |
  | 右肩键 | 向右导览至另一屏幕或部分 |
  | 左/右摇杆 | 移动所选内容 |
  | 方向键 | 移动所选内容 |
  | 主页/标志 | **预留给系统控制** |
  | 菜单 | 打开游戏设置或暂停玩游戏 |
- **支持多个连接的控制器**；**优先使用符号而非文本指代控制器元素**（SF Symbols 提供大多数元素符号）。

### 键盘（游戏键绑定）
- **优先使用单键命令**（单键执行更轻松快捷，同时用鼠标/触控板时尤其如此）；
  可将菜单项首字母作快捷键（I 用于 Inventory、M 用于 Map），主操作映射到**空格键**。
- **使用 Apple 键盘测试键绑定舒适度**——非 Apple 键盘的 Control 键应重新映射到 Apple 键盘的 **Command 键**
  （紧邻空格键，便于使用 W/A/S/D 时触及）。
- **考虑按键的邻近性**（W/A/S/D 附近定义高价值命令；数字键用于库存类别）。
- **让玩家自定义键绑定。**

### visionOS
**使空间游戏控制器行为匹配手部输入**——支持注视对象并按下左/右扳机进行**间接交互**，
或伸手并按下扳机进行**直接交互**。

## 九、其余输入方式（要点）

| 输入 | 关键要求 |
|---|---|
| **操作按钮**（watchOS） | 让用户在不看屏幕的情况下发起基本操作；不占用其给系统的既有行为 |
| **Apple Pencil 和随手写** | 精确输入与手写转文本；与触控输入配合；Apple Pencil Pro 可提供触感反馈
| **相机控制** | 设备上的专用相机控制交互；App 应按系统方式响应 |
| **陀螺仪和加速计** | 用设备姿态/运动作为输入；避免需要特定身体动作；提供替代输入方式 |
| **近场交互** | 靠近设备间的交互；需明确许可与适度提示 |

> 以上四项的完整规则请在需要时查阅官方对应页面（见 `ref-09-catalog.md`）。
