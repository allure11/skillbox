# Apple HIG UI Standard（Apple 人机界面指南 · UI 设计规范）

## Overview

本技能固化 Apple 官方《人机界面指南》中**可执行、可校验**的设计规约，覆盖设计原则、布局、字体排印、颜色与深色模式、
无障碍、组件、动效与反馈、交互模式九大领域，作为所有 UI/交互设计任务的**最高优先级规范来源**。

规范分三级执行（对标 HIG 自身的优先级语义）：
- **【强制】**：可量化、可校验的硬约束（尺寸、对比度、字号、适配要求）。**任何场景不得违反**
- **【推荐】**：HIG 明确的最佳实践。默认遵守，偏离需向用户说明理由
- **【参考】**：平台差异与实现细节，按目标平台取用

规范分两级加载：
- 本文件：**核心强制条款（数字与硬约束）+ 强制工作流 + 交付前自查清单**，每次任务必读
- `references/`：**分领域全量规约**（含平台差异与官方原文要点），遇到对应场景必须查阅

## 强制工作流（每次 UI 任务都必须走完）

### 第 1 步 · 开工前确认三件事
动手设计前必须先明确并向用户声明（未明确时按最合理假设并标注）：

1. **目标平台**：iOS / iPadOS / macOS / watchOS / tvOS / visionOS（多平台需逐一适配，不得只做一套）
2. **输入方式**：触控 / 指针 / 键盘 / 遥控器 / 眼动与手势 / 语音
3. **外观模式**：浅色 / 深色 / 自动，以及是否需支持"增强对比度""减弱动态效果""更大字体"

然后按需打开对应 references：
- 设计原则、价值取向 → `references/ref-01-design-principles.md`
- 布局、安全区、屏幕尺寸、窗口适配 → `references/ref-02-layout.md`
- 字号、字体层级、动态字体 → `references/ref-03-typography.md`
- 配色、语义色、深色模式 → `references/ref-04-color-dark-mode.md`
- 无障碍（对比度、点击目标、旁白、动效减弱）→ `references/ref-05-accessibility.md`
- 按钮与组件选型 → `references/ref-06-components.md`
- 动效、反馈、加载 → `references/ref-07-motion-feedback.md`
- 模态、引导、搜索、表单、设置等交互模式 → `references/ref-08-patterns.md`
- 官方全量主题索引（需要其它主题时查这里）→ `references/ref-09-catalog.md`

### 第 2 步 · 设计时对照核心条款
产出（设计稿/HTML 原型/SwiftUI/前端代码）过程中，对照下方「核心强制条款」逐项自查，
**禁止**出现任何【强制】条款的反例。数字类条款必须落到具体数值，不得凭手感。

### 第 3 步 · 交付前跑一遍自查清单
交付前必须对照「交付前自查清单」逐项确认，并**明确告知用户"已按 Apple HIG 自查"**；
发现违规必须先修正再交付。若因业务原因必须偏离【强制】条款，须显式指出并说明代价。

## 核心强制条款（数字与硬约束 · 每次任务必读）

### 一、点击/交互目标尺寸【强制】
1. **最小可点击区域**必须满足目标平台的"默认控制大小"：iOS/iPadOS **44×44 pt**、macOS **28×28 pt**、
   watchOS **44×44 pt**、visionOS **60×60 pt**、tvOS **66×66 pt**。
   绝对下限（仅在极端受限时）：iOS/watchOS/visionOS **28×28 pt**、macOS **20×20 pt**、tvOS **56×56 pt**。
2. **控制间距**与尺寸同等重要：**有外框**的元素四周留 **约 12 pt** 内边距；**无外框**的元素四周留 **约 24 pt**。
3. visionOS 中按钮中心之间**至少相距 60 pt**；按钮 ≥60 pt 时四周再加 **4 pt** 内边距防悬停效果重叠。

### 二、文字与字号【强制】
4. **不得小于平台最小字号**：iOS/iPadOS **11 pt**（默认 17）、macOS **10 pt**（默认 13）、
   tvOS **23 pt**（默认 29）、visionOS **12 pt**（默认 17）、watchOS **12 pt**（默认 16）。
5. **支持文字放大至少 200%**（watchOS App 至少 **140%**），且放大后**不截断关键文本、不重叠、层级不塌陷**。
6. **避免使用细体字重**（极细体/纤细体/细体）；小字号场景尤其禁用。优先常规体/中黑体/中粗体/粗体。
7. **优先使用系统内建文本样式**（Large Title / Title / Headline / Body / Caption…）而非自造字号体系；
   自定义字体也必须实现动态字体与无障碍响应。

### 三、颜色与对比度【强制】
8. **文字对比度最低标准**（WCAG AA 口径）：
   - 字号 **≤17 pt** → 对比度至少 **4.5:1**
   - 字号 **≥18 pt** → **3:1**
   - **粗体**文本 → **3:1**
   - 自定义前景/背景色**目标 7:1**，小文本尤其如此
9. **禁止仅用颜色传达信息**（区分对象、表达可交互性、传达状态）。必须同时提供文本标签、形状或图标等第二种线索。
10. **禁止硬编码系统颜色值**；必须使用语义化颜色 API（`label`/`secondaryLabel`/`separator` 等），
    且**不得篡改语义色用途**（如把 separator 当文字色、把 secondaryLabel 当背景色）。
11. **自定义颜色必须同时提供浅色/深色变体**，并为每种变体提供高对比度版本；
    即使只推出单一外观，也应提供浅色与深色以适配系统。
12. **同一颜色不得指代不同含义**；颜色语义需考虑跨文化差异（如红/绿在中国与西方股市含义相反）。

### 四、深色模式与外观【强制】
13. **禁止提供 App 专属的外观开关**；必须遵循系统外观设置（含"自动"随昼夜切换）。
14. 深色模式下**同时验证"增强对比度""降低透明度"**打开时的可读性；
    深色背景上的深色文字、低对比文本一律不合格。
15. 深色模式使用**基本色/提升色**两组背景色表达层级：底层界面用基本色（更暗），
    前景浮层（弹窗、模态表单）自动变提升色（更亮）。**优先系统背景色**，不自定义。

### 五、布局与适配【强制】
16. **内容必须位于安全区内**，避开灵动岛、相机防护罩、圆角、工具栏、标签页栏等遮挡。
17. 内容/背景要**延伸到屏幕边缘**；可滚动区域要能滚到屏幕底部与两侧。
18. **动态字体、RTL 语言、横竖排、分屏/窗口缩放、外接显示器**均需适配；
    窗口变窄时**优先维持布局稳定**，全屏版不再适配时才降级为紧凑视图。
19. 阅读顺序因语言而异，RTL 语言下重要元素的"顶部/前端"位置需镜像考量。
20. 平台专属禁区：iOS **避免全宽按钮**；macOS **禁止把关键控制放在窗口底部**、
    **禁止在顶部相机防护罩区域放内容**；tvOS 内容内缩（上下 **60 pt**、左右 **80 pt**）。

### 六、按钮与组件【强制】
21. 每个按钮必须**清晰传达用途**：图标需用用户熟悉的语义（优先 SF Symbols），文本标签用**动词开头**、
    标题式大写、简洁。
22. 自定义按钮**必须提供按压状态**，否则用户会认为按钮无响应。
23. **每个视图只保留 1–2 个突出按钮**；多个选项需要区分优先级时，**用样式而非尺寸**区分。
24. **破坏性操作绝不分配"主要"角色**（即使它是最可能的操作）；主要角色给最可能的**非破坏性**操作。
25. 不使用按钮承载"看起来像 App 里的 App"的复杂层级；不可交互元素不得使用与可交互元素相同/相近的品牌色。

### 七、无障碍【强制】
26. 所有可交互元素必须提供**可被"旁白"识别的标签**；图片/图标按钮必须有描述。
27. **核心功能不得仅依赖复杂手势**：手势必须提供屏幕上的替代方案（如轻扫删除 → 同时给删除按钮）。
28. 支持**减少动态效果**、**减弱闪烁光线**、**全键盘控制**、**语音控制**等系统无障碍开关；
    动效不得是传达信息的唯一方式（需配触感/音频/视觉替代）。

### 八、动效与反馈【强制】
29. **动效必须有目的**，禁止无意义动画；避免在频繁交互上添加动态效果。
30. **动效必须可取消/不阻塞**：不让用户等待动画完成才能操作。
31. **禁止使用快速移动与闪烁动画**；开启"减弱动态效果"时须：收紧弹簧、跟随手势、
    不为 z 轴深度变化加动画、用渐变替代 x/y/z 过渡、不为出入模糊加动画。
32. **反馈的打断级别必须与信息重要性匹配**：状态信息用非侵入式展示；可能不可逆数据丢失才用模态警告；
    数据丢失是用户预期结果时**不要**警告。**绝不同时显示多个提醒**。

### 九、加载与模态【强制】
33. **先显示内容再补细节**：加载时给占位符（文本/图形/动画），不留空白；已知时长用确定型进度指示符，
    未知时长用不确定型；加载期间尽量允许用户做别的事。
34. **模态必须只用于有明确益处的场景**，任务应短小精炼；**必须提供明显的关闭方式**
    （遵循平台惯例，如 iOS 顶部按钮/下拉轻扫）；关闭可能导致数据丢失时须先确认。
35. **模态内避免再套模态**；绝不同时显示多个提醒。

## 交付前自查清单（逐项确认，违规先修再交付）

1. 所有可点击元素是否 ≥ 目标平台最小控制尺寸（iOS 44×44pt 等），间距是否达标（有框 12pt / 无框 24pt）？
2. 所有字号是否 ≥ 平台最小字号，且放大到 200%（watchOS 140%）后无截断/重叠/层级塌陷？
3. 是否避免使用细体字重，且优先使用系统文本样式？
4. 所有文字对比度是否达标（≤17pt 4.5:1；≥18pt 或粗体 3:1；自定义色目标 7:1）？
5. 是否存在仅靠颜色传达信息的地方？是否已补第二线索（文本/形状/图标）？
6. 是否使用了语义化系统颜色，没有硬编码色值、没有错用语义色？
7. 自定义颜色是否提供浅色/深色 + 高对比度变体？
8. 是否遵循系统外观设置，未提供 App 专属外观开关？深色模式下是否验证过增强对比度/降低透明度？
9. 内容是否在安全区内，且延伸到屏幕边缘？滚动能否到达底部与两侧？
10. 是否考虑了横竖排、动态字体、RTL、窗口缩放/分屏、外接显示器？
11. 是否触犯平台禁区（iOS 全宽按钮 / macOS 窗口底部关键控制 / tvOS 安全区内缩）？
12. 按钮是否用途明确、有按压状态、每视图 1–2 个突出按钮、破坏性操作未用主要角色？
13. 所有可交互元素是否都有旁白标签？复杂手势是否都有替代操作？
14. 动效是否有目的、可取消、不闪烁，且在"减弱动态效果"下正确降级？
15. 反馈强度是否匹配信息重要性？加载是否有占位符与合适的进度指示符？模态是否可明显关闭且未嵌套？
