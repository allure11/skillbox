# 文案编写与视觉素材（Writing & Assets）

> 来源：Apple HIG《编写》《SF 符号》《图标》《App 图标》《图像》。
> 覆盖：界面文案、符号系统、界面图标、App 图标、位图与分层图像。

## 一、编写（Writing）

**确定 App 的风格。** 想清楚在和谁说话——银行 App 的词传达信任与稳定，游戏的词传达兴奋与乐趣。
建一份**常用术语表**并在全 App 保持一致。

**语气随上下文变化。** 用户刚完成目标 vs 刚收到错误提示，同一 App 的语气应当不同（前者轻快祝贺，后者直截了当）。

**力求清晰明确。** 选浅显易懂的词，用尽可能少的词，**写完大声朗读一遍**。

**面向所有用户编写。** 避免行话、性别术语、文化特定梗，为无障碍与本地化留余地。

### 最佳实践
- **考虑每个屏幕的用途**：最重要的信息放最前面；信息点过多时拆到多个屏幕。
- **务必注重行动**：按钮和链接用**动词**开头。优先清晰，别耍小聪明——用「发送」而不是「我们开始吧！」。
  链接避免「点按此处」，用「了解有关用户体验编写的更多信息」这类描述性文字（对屏幕朗读器尤其重要）。
- **构建语言模式**：一致的措辞营造熟悉感，也让后续编写更省力。
- **大写规则**：实词首字母大写（Title Case）偏正式，句子首字母大写偏随意。**为每类 UI 元素选定一种并全 App 一致**。
- **多步骤流程指引一致**：开头用「开始使用」表明进入流程；中间用「继续」或「下一步」并保持一致；结束用「完成」明确收尾。
- **谨慎使用所有格代词**：「个人收藏」与「你的个人收藏」信息量相同但更简洁。需要时保持一致、不切换视角。
  **完全避免「我们」**——「我们在加载此内容时遇到了问题」不如「无法加载内容」清晰。
- **按设备调整用词**：触控设备用「轻点」，不要写「点按」。iPhone/Apple Watch 要求简洁；
  TV 在公共空间播放（要考虑周围有谁），且文字必须够大以便远处看清。
- **空白屏幕必须给出后续步骤**：空待办、空书签是欢迎用户并指导使用的好机会，提供可执行按钮或链接。
  空白状态通常是**暂时的**，不要把关键信息放在这里。
- **错误信息**：尽量显示在问题旁边、不指责用户、明确告知修复方法。
  - ✅「选择一个包含至少 8 个字符的密码」
  - ❌「密码太短」
  - 不用「哎哟！」「哎呀」等感叹词——听起来不真诚。
  - 避免「姓名无效」这类机械信息；✅「仅使用字母作为你的名字」。
- **选择正确的传达方式**：按信息紧迫性和重要性决定用通知 / 提醒 / 操作表单，并使用匹配情况的语气。
- **设置标签要清晰简单**：必要时加解释，**描述设置打开时会发生什么**（用户可由此推断关闭时的状态）。
  需要引导用户去某个设置时，**给直接链接或按钮**，不要描述位置。
- **文本栏中显示提示**：清楚标记所有栏位，用提示或占位符说明格式，例如 `name@example.com`。

> 平台考量：**无针对任何平台的额外考量因素**——文案规则全平台通用。

## 二、SF 符号（SF Symbols）

SF 符号与 San Francisco 系统字体无缝整合，**自动适配所有粗细和字号**。

> ⚠️ **版权红线**：不得在 **App 图标、标志或任何商标用途**中使用 SF 符号（或易混淆的相似图像）。
> 描绘 Apple 产品和功能的符号受版权保护，**可以在 App 中显示但不能自定义**。

### 渲染模式（四种）
| 模式 | 说明 |
|---|---|
| **单色** | 一种颜色应用到所有层 |
| **分层** | 一种颜色，但**不透明度按层级别变化**，产生景深感 |
| **调色盘** | 两种或更多颜色，每层一种 |
| **多色** | 为部分符号应用**有内涵的颜色**以增强含义（`leaf` 绿、`trash.slash` 红） |

- **务必用系统提供的颜色**——自动适配无障碍调节、虚化效果与深色模式。
- **确认渲染模式在每种环境下都能正常工作**：不同模式可能影响细节辨识度，取决于符号大小与背景对比度。

### 渐变与可变颜色
- **渐变渲染**（SF Symbols 7+）：从单源色生成平滑线性渐变。任何尺寸都可渲染，**更大尺寸观感更佳**。
- **可变颜色**：表现可随时间变化的特征（容量、强度），按 0%~100% 阈值把颜色应用到不同层。
  - 例：`speaker.wave.3` 的三个声波层分别映射到不同分贝区间；无声时声波层不接收颜色。
  - **用可变颜色传达变化，不要用它传达深度**——深度请用分层渲染模式。

### 粗细与比例
- **九种粗细**（极细体 → 黑体），每种对应 San Francisco 的一种粗细，可与周围文本精确匹配。
- **三种比例**：小 / 中（默认）/ 大，相对**大写字高**定义，用于调整符号相对文本的突出程度而不影响粗细一致。

### 设计变体
- **轮廓**：最常见，无实心区域，与文本外观类似。
- **填充**：部分形状区域为实心。
- **斜线**（表示不可用）、**包围**（圆形/正方形/矩形，符号较小时提高辨识度）——可与轮廓/填充组合。
- **判据**：文本旁显示用轮廓；iOS 标签页栏、轻扫操作、用强调色表示选中处用填充。
  多数情况下**显示符号的视图会决定变体**，无需指定。

### 动画（SF Symbols 提供）
出现、消失、弹跳、缩放、脉冲、可变颜色、替换（缩小至放大 / 放大至放大 / 关闭至放大）、
魔术替换（默认；相关形状间的智能过渡）、摇摆、呼吸、旋转、绘制出现/绘制消失。

- ⚠️ **巧妙应用**：动画数量无上限，但**过多会导致界面杂乱和用户分心**。
- **确保动画意图明确**：每种动画有各自的移动方式与语义，考虑用户会如何理解。
- **用符号动画更高效地传达信息**：以简单方式呈现复杂信息，不占用大量视觉空间。
- **添加动画时考虑 App 的基调**（与品牌标识、整体风格一致）。

### 自定义符号
- 从**类似符号的模板导出后修改**，在细节、视觉粗细、对齐、位置、视角上与系统符号保持一致：
  **简单、易于辨识、具有包容性、与所表示的操作直接相关**。
- 按需分配**负边距**实现视觉水平对齐（命名模式如 `left-margin-Regular-M`）。
- **优化图层以支持动画**：在 SF Symbols App 中给图层加注解；考虑绘制完整形状而非镂空。
- **避免自制常用变体**（封闭形状、标记）——用组件库生成，保持风格一致。
- **必须提供备选文本标签**（无障碍描述）。
- **不要以 Apple 产品为设计原型。**

## 三、界面图标（Icons）

*界面图标* ≠ *App 图标*：前者用精简形状和适量颜色直截了当传达意图；后者可用阴影、纹理、高亮等丰富细节。

### 最佳实践
- **打造可识别且高度精简的设计**：细节过多会导致混乱难懂，优先用熟悉的视觉隐喻直接反映操作或内容。
- **保持 App 内所有界面图标的视觉一致性**：无论纯自定义还是与系统图标混用，
  **大小、细节程度、线条粗细、透视**都必须一致。按图标的**视重**调整尺寸以达到视觉一致。
- **通常使界面图标与相邻文本在线条粗细上一致**。
- **必要时为自定义图标加内边距实现视觉对齐**：非对称图标按几何居中会显得偏离中心，
  把额外像素包含进内边距后即可按几何居中。调整通常极小但对外观影响很大。
- **仅在必要时提供已选状态版本**：工具栏、标签页栏、按钮中系统会自动更新已选外观；工具栏中已选图标应用强调色。
- **使用包容性图像**：优先中性人物形象，避免跨文化难理解的图像。
- **图标中只包含表达含义必要的文本**：需显示单个字符时**必须本地化**；需表示一段文本时用抽象表示，
  并提供**翻转版本**以适配 RTL 环境。
- **自定义界面图标用 PDF 或 SVG 等矢量格式**（系统自动缩放到高分辨率，无需多版本），
  这与 App 图标使用的 PNG 不同（PNG 不支持缩放）。
- **为自定义图标提供备选文本标签。**
- **避免使用 Apple 硬件产品模型**（硬件设计变化频繁会显得过时）。

### 标准图标（常用操作对应的符号）
| 分类 | 操作 → 符号 |
|---|---|
| 编辑 | 剪切 `scissors`、拷贝 `document.on.document`、粘贴 `document.on.clipboard`、完成 `checkmark`、取消/关闭 `xmark`、删除 `trash`、撤销 `arrow.uturn.backward`、重做 `arrow.uturn.forward`、编写 `square.and.pencil`、复制 `plus.square.on.square`、重命名 `pencil`、移到 `folder`、附上 `paperclip`、添加 `plus`、更多 `ellipsis` |
| 选择 | 选择 `checkmark.circle`、取消选择 `xmark` |
| 文本格式化 | 上标 `textformat.superscript`、下标 `textformat.subscript`、粗体 `bold`、斜体 `italic`、下划线 `underline`、左对齐 `text.alignleft`、居中 `text.aligncenter`、两端对齐 `text.justify`、右对齐 `text.alignright` |
| 搜索 | 搜索 `magnifyingglass`、查找 `text.page.badge.magnifyingglass`、过滤 `line.3.horizontal.decrease` |
| 共享导出 | 共享 `square.and.arrow.up`、打印 `printer` |
| 用户账户 | 账户/用户/个人资料 `person.crop.circle` |
| 评分 | 不喜欢 `hand.thumbsdown`、喜欢 `hand.thumbsup` |
| 层叠顺序 | 移至最前 `square.3.layers.3d.top.filled`、移至最后 `…bottom.filled`、前移 `square.2.layers.3d.top.filled`、后移 `…bottom.filled` |
| 其他 | 闹钟 `alarm`、归档 `archivebox`、日历 `calendar` |

### macOS 文稿图标
- 传统外形为**右上角向内折叠的纸**，最小时显示为 **16×16 像素**，所以设计必须在任何大小下可识别。
- 可组合**背景填充 + 中心图像 + 文本**，系统按需分层、定位、遮罩并合成。
- **避免把重要内容放在背景填充的右上角**（系统会遮挡以适配形状并绘制白色折角）。
- 背景图像尺寸：512@1x/1024@2x、256@1x/512@2x、128@1x/256@2x、32@1x/64@2x、16@1x/32@2x。
- 中心图像占画布**一半**；**外边距约占画布 10%**，图像占画布 **80% 左右**时效果最佳。
- **降低小尺寸版本的复杂度**：16×16@2x 可保留主要线条但去掉网格线；16×16@1x 可完全去掉细线。

## 四、App 图标（App Icons）

### 分层设计
- **iOS、iPadOS、macOS、watchOS**：背景层 + 一个或多个前景层，具备**镜面高光、折射、半透明**等 Liquid Glass 属性。
- **Apple tvOS**：**2~5 个叠层**，聚焦时提升至前景、表面发光并轻微摇摆，形成**视差效果**。
- **visionOS**：背景层 + 上方 1~2 层，形成**三维对象**，系统加阴影体现层间深度、用上层 Alpha 通道打造浮凸感。

要点：
- **前景层首选清晰边缘**——避免柔和/羽化边缘，以便系统更好地绘制高光与阴影。
- **改变前景层不透明度**以增加深度感和生动感。
- **背景层要醒目且强调前景内容**：优先纯色或渐变；如导入背景图，须**全幅且不透明**。
- **导入时首选矢量图形**（SVG/PDF），栅格插图用 **PNG**（无损）。

### 图标形状（系统会遮罩）
| 平台 | 提供形状 | 系统遮罩后 | 布局尺寸 | 样式 | 外观变体 |
|---|---|---|---|---|---|
| iOS、iPadOS、macOS | 正方形 | 圆角矩形 | **1024×1024 px** | 分层 | 默认 / 深色 / 透明浅色 / 透明深色 / 色调浅色 / 色调深色 |
| Apple tvOS | 矩形（横向） | 圆角矩形 | **800×480 px** | 分层（视差） | — |
| visionOS | 正方形 | **圆形** | **1024×1024 px** | 分层（3D） | — |
| watchOS | 正方形 | **圆形** | **1088×1088 px** | 分层 | — |

- **创建形状合适的未遮罩层**：提供**带预定义遮罩的层会破坏镜面高光效果并使边缘出现锯齿**。
- **保持主要内容居中**，避免系统调整圆角或遮罩时被截断。

> 色彩空间支持：sRGB（颜色）、灰度系数 2.2（灰度）、Display P3（广色域，仅 iOS/iPadOS/macOS/tvOS/watchOS）。

### 设计要点
- **拥抱简洁**：优先简单背景（纯色/渐变），不必填满整个画布；精细特征经系统阴影与高光渲染后可能显得杂乱。
- **为所有支持的平台提供视觉一致的图标设计。**
- **考虑基于实心的重叠形状**，与透明和模糊效果搭配时深度感更好。
- **仅在文本对体验或品牌不可或缺时才包含文本**（不支持无障碍和本地化，通常太小难看清）；
  避免「全新」「观看」等非必要字词或语境特定词。
- **优先插图而非照片**，避免复制标准 UI 组件或 App 截屏；避免极细线条和锐角。
- **不要以 Apple 硬件产品为设计原型。**

### 视觉效果与外观
- **让系统处理模糊及其他视觉效果**（镜面高光、层间投影、斜角、模糊、光晕）。
  自定义效果是**静态**的，系统效果是**动态**的——如确需添加，须在真机/模拟设备上仔细测试。
- **创建层群组**以将效果一次性应用到多层。
- **在各种外观下保持图标特征一致**，避免在变体间替换元素导致用户难以找到 App。
- **深色图标**：以浅色图标为基础，选补充色，避免过亮图像；颜色背景通常对比度更好。
- **考虑提供备选 App 图标**（如体育 App 按球队）；每个备选图标的深色/透明色/色调变体也需提交审核。

### 平台差异
- **tvOS**：包括**安全区域**（聚焦时系统会缩放移动并裁剪边缘，前景层裁剪多于背景层）。
- **visionOS**：**避免背景层中出现看起来像孔洞或凹面的形状**（系统阴影与高光会让其看起来突出）。
- **watchOS**：**避免黑色图标背景**——调亮黑色，否则图标会融入显示屏背景。

## 五、图像（Images）

### 分辨率与格式
- **点**是抽象计量单位：2D 平台中点映射到一定数量像素（随屏幕分辨率而异）；**visionOS 中点是角度值**。
- **缩放系数**：@1x 为 1:1，@2x 为 2:1，@3x 为 3:1。

| 平台 | 缩放系数 |
|---|---|
| iPadOS、watchOS | @2x |
| iOS | @2x 和 @3x |
| visionOS | @2x 或更高 |
| macOS、Apple tvOS | @1x 和 @2x |

- **在支持的每台设备上为所有位图提供高分辨率资源。**
- **一般以最低分辨率设计再放大**；用矢量形状时把控制点放在整数值上，便于在 1x 下与光栅网格整齐对齐。

| 图像类型 | 格式 |
|---|---|
| 位图/光栅插图 | 去交错 **PNG** |
| 不需要 24 位真彩的 PNG 图形 | 8 位调色盘 |
| 照片 | **JPEG**（按需优化）或 **HEIC** |
| 立体/空间照片 | 立体 **HEIC** |
| 需要高分辨率缩放的扁平化图标、界面图标、扁平插图 | **PDF 或 SVG** |

- **每个图像包含一个颜色描述文件**（确保跨显示器颜色一致）。
- **始终在一系列实际设备上测试图像**——设计时漂亮的图在不同设备上可能被像素化、拉伸或压缩。

### 平台差异
**Apple tvOS — 视差与分层图像**
- **分层图像由 2~5 层叠加**，层间分离与透明度形成深度感；交互时靠近表面的层提升并缩放，底层向后重叠形成三维效果。
- **tvOS App 图标必须使用分层图像**；其他可获得焦点的图像（含推荐项目）**强烈建议**使用。
- **识别逻辑前景、中间、背景元素**：前景层放重要元素（角色、专辑封面或海报上的文本）；
  中间层放二级内容和效果（阴影）；背景层不透明，展示前两层又不抢风头。
- **文本通常应放在前景中**（除非想要模糊文本）。
- **背景层必须不透明**，否则会报错。
- **分层应简单且不易察觉**——过度三维效果会显得不真实且不协调。
- **在前景层周围留出安全区域**（聚焦时可能因缩放移动被裁剪）。
- **始终预览分层图像**（Xcode / Parallax Previewer / Photoshop Parallax Exporter），最终**在实际电视上预览**。

**visionOS — 空间照片与空间场景**
- **创建分层 App 图标**（2~3 层，聚焦时以不同速度移动提供深度外观）。
- **2D 图像首选基于矢量的插图**，避免位图被系统放大后呈现不良。
- 必须用栅格图时**在质量与性能间平衡**：@2x 常规视距美观但不会动态缩放；
  分辨率超过 **@6x** 尤其可能影响运行时性能，高于 @2x 时须同时应用高质量图像滤波。
- **空间照片**用立体 HEIC 格式（含空间元数据）；**空间场景**由 2D 图像生成 3D，带随头部移动的视差。
- **空间照片上显示文本时首选羽化玻璃背景效果**（增强对比度、模糊细节以减轻视觉不适）。
- **在独立视图中显示空间照片和空间场景**，避免与其他内容内联（会加重视觉不适）；必须内联时留充足间距。
- **沉浸显示时首选极简 UI**；**优先显示较大空间场景且放在视野中央**。

**watchOS**
- **一般避免使用透明度**以保持图像文件较小；仅在复杂功能图像、菜单图标、模板图像等必要处使用。
- **使用自动缩放 PDF**为所有屏幕尺寸提供单一素材，按 40mm/42mm 设计 2x 图像：

| 缩放 | 90% | 100% | 106% | 100% | 110% | 119% | 119% |
