# 布局（Layout）

> 来源：Apple HIG《布局》。适配各种环境的一致布局可帮用户在所有设备上享用 App。

## 最佳实践

- **将相关项目分组**，帮助用户找到想要的信息：用负空间、背景形状、颜色、材质或分隔线区分相关与不相关元素；确保内容与控制之间有明显区别。
- **为重要信息留出足够空间**：不要把它与次要细节挤在一起；次要信息可放到窗口其他部分或附加视图中。
- **扩展内容以填满屏幕或窗口**：背景与全屏插图延伸至显示屏边缘；可滚动布局能持续滚到设备屏幕底部和两侧。
- **控制与导览组件显示在内容之上而非同一平面**（边栏、标签页栏），布局时须考虑这一点。
- 内容未占满窗口时，用背景扩展视图在屏幕两侧的控制层后面提供内容外观。

## 视觉层次

- **将控制和内容区分开来**：充分利用 Liquid Glass 材质为控制提供跨 iOS/iPadOS/macOS 一致的独特外观；
  使用**滚动边缘效果**而非背景来提供内容与控制区域之间的过渡。
- **项目放置应传达相对重要性**：用户通常按阅读顺序查看（从上到下、从前到后），
  最重要的项目放在窗口/显示/视场顶部和前端附近。**阅读顺序因语言而异**，需把 RTL 语言纳入考量。
- **将组件互相对齐**：对齐让界面整洁有序，帮助用户在滚动时跟踪内容；可搭配缩进表达信息层级。
- **利用渐进显示**：无法一次显示全部项目时，要提示还有更多（显示控制或展示项目的一部分）。
- **控制四周留足够空间并分组到合理分区**：不相关控制距离过近会导致难以区分和操作。

## 适配性（必须处理的环境变化）

- 不同的设备屏幕尺寸、分辨率和色彩空间
- 不同的设备方向（竖排/横排）
- 各种系统功能，如灵动岛和相机控制
- iPad 上的外接显示器支持、缩放显示和可调整大小的窗口
- 动态字体文字大小更改
- 基于区域设置的国际化（LTR/RTL 布局方向、日期/时间/数字格式、字体变体、文本长度）

要点：
- **设计完美适应环境变化且视觉一致的布局**：遵循系统定义的安全区、外边距和指南。
- **事先考虑文字大小变化**：支持动态字体时，App 应随用户调整字号而适当响应。
- **在多台设备上使用不同方向、本地化语言和文字大小预览**：先测最大和最小布局版本；横排需验证左右两个旋转方向。
- **必要时缩放插图以响应显示更改**：出现裁剪或信箱/邮筒模式时，**不要更改宽高比**，而应缩放插图保持重要内容可见。

## 指南和安全区

- **布局指南**：定义矩形区域帮助放置、对齐和间隔内容；系统提供预定义布局指南（标准外边距、限制文本宽度以优化可读性）。
- **安全区**：定义视图中不会被工具栏、标签页栏或其他视图遮挡的区域；对避开灵动岛、相机防护罩等设备特性必不可少。
- **遵循每个平台中的关键显示和系统特性**：不适应会让 App 显得格格不入且更难上手；安全区会在尺寸更改时动态调整内容位置。

## 平台考量因素

### iOS
- **力争同时支持竖排和横排**；仅支持横排时，需确保左右两个旋转方向都正常。
- **首选为游戏使用全幅界面**；必要时可提供信箱/邮筒模式选项。
- **避免使用全宽按钮**：按钮应遵循系统定义外边距从屏幕一侧嵌入；必须用全宽按钮时，要与硬件弧度协调并与相邻安全区对齐。
- **仅在有好处时才隐藏状态栏**：玩游戏、看媒体等深度体验场景可例外。

### iPadOS
- 用户可自由调整窗口大小（类似 macOS），设计时须考虑所有可能的窗口尺寸范围。
- **尽可能推迟切换至紧凑视图**：优先为全屏设计，仅在全屏布局不再适配时才降级；复杂布局（如分屏）应优先隐藏次要栏（如检查器）。
- **采用系统提供的常见大小测试布局**（填充屏幕的 1/2、1/3、1/4），并提供流畅过渡。
- **考虑为自适应导览采用可转换的标签页栏**（首次启动显示边栏或标签页栏，之后可轻点切换，呈现样式随视图宽度变化）。

### macOS
- **避免将控制或关键信息放在窗口底部**：用户常移动窗口导致底部边缘落到屏幕下方。
- **避免在窗口顶部边缘的相机防护罩内显示内容**。

### Apple tvOS
- **事先考虑各种电视机尺寸**：tvOS 布局不会自动适配屏幕尺寸，所有显示屏显示相同界面。
- **遵循屏幕安全区**：主要内容距屏幕顶部和底部 **60 pt**、距两侧 **80 pt**；
  仅部分显示的离屏内容和故意延伸出屏幕的元素可在此区域外。
- **在可获得焦点的元素之间包括适当内边距**：元素获得焦点时会变大，避免与重要信息重叠。

#### tvOS 网格规范（示例：两列网格）
| 属性 | 值 |
|---|---|
| 未获得焦点内容宽度 | 860 pt |
| 水平间距 | 40 pt |
| 最小垂直间距 | 100 pt |

- 有标题的行需留更多垂直间距（上一行底部到标题中心、标题底部到该行项目顶部）。
- **使用一致的间距**，否则看起来不再像网格。
- **让部分隐藏的内容对称**：屏幕每一侧保持相同的露出宽度。

### visionOS
- **将最重要的内容和控制居中放置**：内容位于窗口中间附近更易发现和交互，窗口较大时尤其如此。
- **保持窗口内容位于其边界内**：系统在窗口边界之外显示窗口控制（共享菜单在上方，调整大小/移动/关闭控制在下方），
  2D/3D 内容侵占这些区域会导致用户难以使用系统控制。
- **需要显示不属于窗口内部的额外控制时使用挂饰**（工具栏和标签页栏即以挂饰形式显示）。
- **让交互式组件易于注视**：按钮中心至少相距 **60 pt**；按钮 ≥60 pt 时四周加 **4 pt** 内边距防止悬停效果遮挡内容。

### watchOS
- **内容从屏幕一侧边缘延伸到另一侧边缘**：Apple Watch 外框已提供自然视觉内边距，应最小化元素间内边距以节省空间。
- **避免并排放置超过两个或三个控制**：一般规则是一行中图标按钮不超过三个、文本按钮不超过两个；
  文本按钮横跨完整宽度通常更好；只要屏幕不滚动，两个带短文本的按钮并排也可接受。
- **在用户可能向他人展示的视图中支持自动旋转**（如展示图片、出示二维码）。

- iPad 全系（竖排/横排）：**常规宽度，常规高度**
- iPhone Pro Max / Plus / Air（竖排）：**紧凑宽度，常规高度**；（横排）：**常规宽度，紧凑高度**
- iPhone 标准/Pro（竖排）：**紧凑宽度，常规高度**；（横排）：**紧凑宽度，紧凑高度**
